# 基于 SLAM 的低速平移响应检测与有限补偿

本模块将 SLAM 定位作为运动参考，但不能据此证明发生了轮地打滑。厂家位置已变化、SLAM 位移偏小时，可能是打滑，也可能是定位滞后；两者都小，则也可能是执行死区、静摩擦或控制链响应不足。日志分别记录 `SUSPECTED_SLIP` 和 `LOW_RESPONSE`，不把它们当作已确诊的机械故障。

## 当前启用状态

- 真机精度配置：`FollowPath.slip.mode: monitor`，采集、对比、记录，指令保持原值。
- 仿真及未选择真机配置的入口：默认 `off`，保持原基线。
- `compensate`：实现了下述有限加速。修改配置后需要重新启动导航控制器；没有实现运行中切换模式的参数回调。

根据用户现场反馈，9 月 17 日的 SLAM 内容滞后来自全话题录包负载，不列入当前问题清单，也不作为打滑补偿验证的前置阻塞。后续在不录制全部话题的正常工况下验证。本地真机配置仍为 `monitor`，原因是自动补偿尚未完成真机实测验收；本次代码未修改厂商 SLAM，也未向真机部署或发送运动命令。

## 数据与算法

控制归属仍在 `ArrivalController`。桥接层不增加第二套 SLAM 位置反馈。

1. 订阅最终下发的机身坐标速度 `/cmd_vel`、SLAM 派生 `/odom` 和厂家位置诊断 `/astribot/chassis/odom_from_sdk`。厂家 odom 的零 twist 不参加计算。Twist 的时间采用本节点接收时刻，因此它代表发送链路的观测，不是 SDK 确认执行时间。
2. 在三路共同覆盖的 1.5 秒窗口中，以源时间插值取两路位置的起止点，按各自窗口起点的机身朝向投影净位移；厂家与 SLAM 的世界坐标原点和航向可以不同，但 child frame 必须是同一机身。窗口内部也检查轨迹连续性，不只看端点。
3. 对同一窗口的最终指令做分段常值积分，得到沿请求方向的指令行程。比较 `SLAM 沿向净位移 / 指令积分行程`。日志同时给出厂家沿向位移和三路窗口平均速度。
4. SLAM 响应比小于 0.35，持续确认 1.5 秒后，才具备补偿条件。从新运动段开始至少需要约 3 秒有效证据。SDK 位移达到指令行程一半时标为疑似打滑/反馈不一致；否则标为低响应。
5. 在 `compensate` 模式下，沿原平移方向加一个最多 2 秒、两端缓升缓降的速度脉冲。增量不超过 `min(0.01 m/s, 原指令 × 35%)`，总平移速度不超过 0.06 m/s。角速度不变。两秒内的额外指令积分上限为 2 cm，**不是实际滑行距离上限**。
6. 响应恢复到 0.65 以上立即撤销增量；原有 jerk 平滑器处理最终输出过渡。若无改善，本次尝试用尽，不继续叠加。只有持续恢复一个窗口或新目标重置后才可再尝试。原有不可达/无进展超时继续生效，不因发送补偿而续期。

仅对 FOLLOW 与 REFINE 中的低速近直线平移生效。HOLD、DONE、起始对齐、原地旋转、窄通道接管、视觉/mark 到位调整、零指令、换向、缺帧、重复时间戳内容冲突、时钟回退、定位跳变均不进行补偿。相同时间戳的相同位置被忽略；无法证明机械打滑的定位异常不会通过自动累加速度处理。

所有增量保留原方向，并受外部限速、策略限速、接近段限速、路径曲率限速及到位停车距离约束。修改后的候选指令再做完整机身扫掠检查；失败时放弃增量，保留原控制器输出。后续 jerk 平滑、执行限速及保护链不变。已经进入到位容差范围时不额外加速。

## 配置

公共数值在 `ws_robot/src/astribot_s1_navigation/config/arrival_motion.yaml`；真机模式在同目录 `arrival_precision_hardware.yaml`。以下参数属于 `FollowPath.slip.*`，单位为 m、s、rad。

| 参数 | 默认值 | 用途 |
|---|---:|---|
| `mode` | off；真机 monitor | off / monitor / compensate |
| `window_s` / `confirm_s` | 1.5 / 1.5 | 同窗比较及持续确认 |
| `max_age_s` | 0.3 | 源时间龄期、断帧与控制循环间隔限制；不能识别伪新时间戳 |
| `min_speed` / `max_speed` | 0.008 / 0.06 m/s | 低速检测范围与补偿总速度上限 |
| `max_angular` / `max_curvature` | 0.03 rad/s / 0.3 m⁻¹ | 同时约束旋转量和指令曲率，仅处理近直线平移 |
| `min_command_distance` | 0.01 m | 避免在积分行程过小的窗口判断响应比 |
| `low_ratio` / `recovery_ratio` | 0.35 / 0.65 | 低响应及恢复阈值 |
| `max_extra_speed` / `max_extra_ratio` | 0.01 m/s / 0.35 | 增量绝对值和相对值上限 |
| `ramp_acceleration` / `attempt_s` | 0.01 m/s² / 2 s | 补偿包络斜率和单次时长 |
| `slam_odom_topic` | /odom | SLAM 位姿参考 |
| `manufacturer_odom_topic` | /astribot/chassis/odom_from_sdk | 厂家位置反馈 |
| `executed_command_topic` | /cmd_vel | 最终机身坐标速度观测 |

特别注意：Gazebo 基线的 `/cmd_vel` 可能已经转成世界坐标。仿真注入测试必须选择或转换成实际机身坐标指令，并提供独立的执行位置反馈话题；不能把同一 `/odom` 同时冒充两种传感器。真机当前入口的 `/cmd_vel` 为机身坐标。

日志为 2 Hz `SLIP_METRICS`，包含时间窗口、`valid`、状态、指令/SLAM/厂家沿向行程及平均速度、响应比、基线速度、建议增量、速度上限。`SLIP_APPLIED` 表示候选通过扫掠检查，`SLIP_REJECTED` 表示未采用。`valid=0` 时的位移/比值不应当作有效打滑样本。实际执行仍以最终 `/cmd_vel` 和反馈数据为准。

## 验证方法与真机验收

本轮检查、脚本和结果在 `runs/slip_compensation_20260917/`；具体结果见其中 `REPORT.md`。场景验证文件用于本次验收，没有增加自动运动的常驻任务。

真机顺序：

1. 不录制全部话题，仅保留本测试所需的速度、位姿和日志。按现有输入时效要求采集；以厂家数据做时序对照，不将厂家绝对位置作为地面真值。
2. 保持 `monitor`，在空旷场地分别以 x+/x−/y+/y− 运行 0.008、0.015、0.03、0.05 m/s 短段。录制上述三路输入、`/cmd_vel_nav_body_raw`、`/path_tracking/phase`、TF 和 session.log。对照现场运动，区分实际低响应、接触障碍与坐标错误。
3. 在确认的同一低响应工况切到 `compensate`，逐个方向复测。检查原速度不被改变方向、角速度不增加、增量不越界、每次最多两秒、不重复加码、恢复后撤销。人工停车及发零指令必须立即终止补偿请求，实际停车距离单独测量。
4. 再做 0.5–1 m 直线与目标末端调整。比较相同路线、相同速度参数下的横向误差、航向误差、指令平滑性及停稳后的 SLAM 相对到位误差。达到 3 cm / 1.5° 且无退化后，才考虑把真机默认模式改为 compensate。
5. 添加停止、反向、陈旧消息、位姿跳变、限速和碰撞风险场景；补偿必须退出，不能改变原本的停止/避障结果。上述故障先用离线或仿真注入验证，不在真机上制造碰撞。

该功能解决的是少量低速执行不足，不处理 0.32–0.33 m/s 巡航指令只有 0.22–0.23 m/s 的整体速度增益偏差。
