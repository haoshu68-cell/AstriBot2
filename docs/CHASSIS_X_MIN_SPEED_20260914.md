## 用户最新一轮的问题

原数据：`runs/x_positive_20260914_171248`。

- 约第 91 秒，在第一轮最高档之后的静止保持阶段触发 SDK 时序保护。当时记录中的指令速度为 0，累计有效平移约 0.4533 m、有效转角约 0.01534 rad，均未越界。
- 原错误将指令租期与循环超时合并，无法从旧日志准确区分；最后 SDK 状态与错误间隔约 0.176 秒。此次增加独立的 `loop_dt_s` 和 `command_age_s` 诊断，0.05 / 0.25 秒限值没有放宽。后续四轮没有复现，但不能据此认定原时序问题彻底消失。
- 停车请求返回后，SDK 确实未在 5 秒内退出。与更早的 0.1 秒误报不同。检查厂家示例后补齐 `middleware.shutdown()`，后续四轮停车请求返回至进程退出约 1.07–1.32 秒，均正常退出。此调用仅收尾测试进程的 middleware，不停止系统中的厂家服务。
- 0.002 m/s 原首次恒速段分三段位移为 1.54、2.40、3.49 mm，第一段低于 1.67 mm 检出门槛，说明低速起步阶段收敛较慢。没有为通过而降低判据，而是延长恒速观察时间并单档复测。
