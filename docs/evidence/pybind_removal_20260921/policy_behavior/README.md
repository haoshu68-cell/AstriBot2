# P2 behavior and path-evidence native core checkpoint

This is preparation for the controller migration. No controller ROS entry, P3/P4/P5/H2 behavior, launch selection or live pybind consumer is removed by this checkpoint.

The three frozen Python reference files are byte-identical to Git 51132768. Optional native behavior is disabled in the authority. The native YieldPolicy now accepts updated envelope/profile limits without resetting its hold, episode or timer state; a future controller must call update_profile before selecting. Its stopping horizon preserves Python addition grouping and skips braking/delay when maximum speed is zero. The previous native constructor differed at zero-speed and adjacent floating thresholds.

Validation: 7 behavior tests (6,000 seeded persistent operations, 3,000 immediate threshold neighbours, fixed live-profile/hold/rollback cases and source hashes) plus 6 path-evidence tests (6,000 seeded independent ROS/wall ages, exact freshness bounds, fallback ordering and every path field). Both the 13 test functions in Release and the same 13 with UBSan pass; they are not additional independent populations when repeated through CTest. The package has separate CTest wrappers for the two suites. No ROS process, performance or hardware acceptance is claimed here.

Path identity compares the outer header, every pose header and all seven finite position/quaternion components. Signed zero compares equal. NaN and infinity are rejected before identity comparison. Evidence fallback precedes age validation, preserving the source ordering. This uses semantic fields, not CDR bytes or a lossy hash.

`missing_profile_api_red.log` shows the old header cannot expose the needed updater. `horizon_red.log` is a real behavioral mismatch against an **intermediate test kernel**: Git 51132768 navigation_math.cpp with only the new updater appended, while retaining the old stopping-horizon expression. Its complete source and build log are kept. It is not an unchanged historical full binary. `green.log` predates the additional horizon test; the final seven-test green result is `ubsan_green.log` and the current Release CTest record `core_tests.log`. The path helper was drafted before its differential test; no test-first RED is claimed for that helper. `package_build.log` is an initial target-configuration mistake, followed by configure and successful build, not a product failure.

Reproduce by building the native package with ASTRIBOT_BUILD_PYBIND=OFF, BUILD_TESTING=ON and C++17/-ffp-contract=off, then running CTest -R 'policy_(behavior|path_evidence)_differential'. For standalone checks set POLICY_BEHAVIOR_PROBE or POLICY_PATH_EVIDENCE_PROBE and run the corresponding pytest file. `path_ubsan_command.json` preserves the exact instrumented compilation inputs; the behavior probe uses navigation_math.cpp plus policy_behavior_probe.cpp with the same undefined-behavior sanitizer flags. `source_manifest.json` identifies code, frozen authority and tested binaries.
