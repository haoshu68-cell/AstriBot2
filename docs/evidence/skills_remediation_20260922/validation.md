# 技能整改验证记录

2026-09-22。范围为技能选择、文档语义、来源定位和文本应用题；没有运行机器人、ROS/Gazebo、进程停止或硬件测试。

## 输入和方法

1. 编辑前冻结全部项目技能，在独立评估上下文中运行 12 道固定题，保留原始 [基线回答](baseline_answers.md)。它是旧技能下的使用试评，不是“完全不使用技能”的对照。
2. 根据已完成的盘点和用户新语言要求整改，冻结修改后的技能；另一个未参与编写的评估者使用相同题设作答，没有提供基线答案、预期答案或整改报告。
3. 另由只读评审者核对当前技能、模板、手册与关键工具源码。应用题和独立文档复核分别记录，不能算成机器人测试。
4. 实际输入文件哈希、本地引用及技能格式检查见 [static_validation.json](static_validation.json)。评估者只按冻结技能答题，源文件未随期间手册引用修正改变。

题设统一保存在 [固定使用题集](../../../.agents/skills/astribot-architecture-design/references/skill-use-cases.md)。下面的判据由组织者用于检查答案，不提前交给答题者。

| 3 | 编辑器、网关、持久化优先 C++；启动/离线验证脚本优先 Python | 主要选择已符合；旧技能仍存在宽泛薄适配例外，不能据本题推导文字政策已一致 |
| 4 | 适配器依赖核心/契约，核心不依赖具体 ROS/SDK；编译方向与调用分开 | 已正确，不归功于本轮整改 |
| 5 | 保留连续命令 Topic，授权、时效、watchdog 及保护链明确 | 已正确识别命令流，不归功于本轮整改 |
| 6 | 拒绝不进入队列，成功不必经暂停/取消；结果与交接区分 | 主要路径已正确；本轮进一步明确独立资源处置及检查点 |
| 7 | ACK/child 成功不覆盖未停稳与写盘失败；隔离冲突资源 | 已正确，不归功于本轮整改 |
| 8 | 排除他人、无归属及复用 PID；不全局删除 DDS/模式杀进程 | 已正确提出安全边界；不能据此证明旧配方或现有工具安全 |

| 11 | 旧链接失效不证明无实现，C++ 文件存在也不证明部署/闭环 | 已正确，不归功于本轮整改 |

## 修改后应用题结果

实际回答保存在 [forward_answers.md](forward_answers.md)。逐题人工核对上表的关键判据，12/12 在本次有限题设下符合；这表示文本使用题符合预期，不是执行了 12 个机器人测试。

- 第 1、2 题不再无条件加载搬运、语言或操作流程，也没有为了整理 CSV 重跑系统。
- 第 3 题明确编辑器、REST 网关和持久化为 C++，启动/离线脚本为 Python。
- 第 4、5 题正确分开源码依赖与运行调用，并保留受控连续命令 Topic。
- 第 6、7 题分开业务结果和资源交接，不要求成功经过取消；未停稳/写盘失败保留隔离。还区分取消“已发送”和“权威已受理”，没有用回调先后代替裁决。
- 第 8～10 题使用会话身份、参数化 domain 和独立 Gazebo 环境；对未知归属和缺观测保留未知，不给出全局清理方案。
- 第 11、12 题不因旧入口消失认定无实现，也不将姿态输出/拒绝升级为抓取成功。

整改前后为两个不同的应用题评估者，但样本小且并非随机实验。基线已有正确行为照常保留，不计算改善率。没有实测任何停止工具、资源 fencing 或消息协议。

## 静态检查结果与边界

最终格式校验 15/15 通过；全部技能 Markdown、根 AGENTS.md 和架构参考手册的 155 处本地引用目标存在。独立只读复核未发现阻断问题，完整结果及版本指纹见 [independent_review.md](independent_review.md)。两个检查范围相同，不把引用数量重复相加。

格式检查只验证入口结构，文件链接检查只验证目标存在；它们不证明规则正确、ROS 接线可用或物理停止安全。扩大到手册的首轮引用检查发现旧 `grid_self_clear_node.py` 链接失效，核对已集成机身处理的 `nav_prob_grid_node.cpp` 后更新；最终检查记录覆盖此修正。

所有试评仅一次有限题集，不是随机盲测、大样本性能对照或穷尽边界证明。后续技能变化复用受影响题目，保留失败输出；不要以不断增加固定清单替代实际问题反馈。
