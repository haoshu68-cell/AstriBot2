# 正常搬运：事件式速度命令适配

本轮只修复阻断正常单箱父任务的命令契约，不增加运行时末级保护，不增加场景矩阵。原有问题及恢复计时保留。

## 事实与改动

scene02 的 150 个原始检查点均未收到 `/cmd_vel`，执行器均为 IDLE，里程计线速度、角速度及位置漂移为零。当前平滑器及坐标转换模块不承诺空闲零命令心跳；旧工装和固定工位导航辅助模块依赖该心跳，导致正常流程无法推进。

C++ 导航辅助模块现在保留命令的“未观测”状态。在父任务独占、尚未发导航的现有契约内，以新鲜里程计的完整原停止窗口确认准入；导航后的停止交接同时要求导航终态、本次导航发送后实际收到的最终零命令及新的完整停止窗口。最后非零命令断流仍失败；迟到的真实零可用于失败收尾，不能改写首因。五个消费者 ACK、里程计时效、600 ms source/steady 窗口、12 样本、停止速度/漂移、TF 与到位阈值均不变。

准备和验收脚本显式使用事件模式；旧调用默认行为保留。冷启动静默需新鲜上游 HOLD 与执行器 IDLE，未知命令不伪造为零。父任务受理后的停止需父终态及任务提交后真实零命令。未获得准备停止窗口不再错误记录为通过。

## 验证边界

- C++ 增量构建及独立前缀安装通过，实际动态链接指向新 `libfixed_station_navigation.so`。
- domain 36 的 6 项隔离 ROS 协议全部通过，首次运行无失败，已记录的自有进程均退出。
- 6 项覆盖：冷启动无命令和单次零到站、缺必要 ACK、取消后实际停止、最后非零断流、成功终态但缺真实零、真实零但缺新鲜里程计。
- M2 报告验证脚本 39 项离线检查通过；根任务独立只读复核调用边界，未将其计为另一轮测试。
- 以上不是完整 Gazebo 搬运验收。新正常单箱场景由 M2 独占执行，需保留 PICK、NAV、PLACE、权威 EMPTY、独立场景读回、子动作终态、资源释放及录屏证据。
