# RViz 上位机 P0—P5 交互与实施方案

日期：2026-09-19。本文为实施设计，不代表功能已全部实现或通过真机验收。依据当前仓库源码与已有设计核对；不改动 SLAM 代码、注释或现行控制链。

关联：[总体设计](RVIZ_OPERATOR_STATION_DESIGN_20260919.md)、[诊断与回放](RVIZ_REPLAY_AND_DELIVERY_PLAN_20260919.md)、[循环导航](RVIZ_LOOP_ROUTE_DESIGN_20260919.md)。本方案细化阶段交付，现有接口与拟新增接口明确区分。

## 1. 产品主线与界面

采用“一个机器人上下文、一份机器人端任务事实、六个工作页”：

- 总览：连接、控制归属、电池、定位、地图版本、载荷、任务进度、录制状态；每项有时间与有效性，未知不能显示成正常。
- 导航与探索：RViz 地图、目标朝向、路线列表、路径与包络、探索状态；操作集中在侧栏。
- 地图与工位：会话列表、版本、保存结果、工位编辑、人工换层向导。
- 机械臂：场景、目标、规划预览、执行反馈、夹爪及持物证据。
- 任务：任务创建、队列、阶段、控制来源、人工处理与恢复。
- 诊断回放：故障列表、事件时间线、RViz/相机、关键参数、证据完整性、导出。

顶部常驻机器人 ID、实时/回放模式、控制归属和连接状态；底部常驻当前任务、告警和实际日志目录。P1 只开放已具备后端的页签功能，未接入功能说明原因，不放可点击的空按钮。RViz 中的“取消任务”不能标为硬件急停。

实时控制窗口与回放窗口采用独立进程/ROS 上下文；回放窗口没有控制客户端。切换机器人先处理当前草稿并明确原任务仍可能运行，禁止把上一机器人的目标、租约或状态带给新机器人。

## 2. 所有操作共用的交互契约（P0 冻结）

### 2.1 提交与反馈

流程：选择对象 → 本地草稿/预览 → 后端前置检查 → 提交 → 已受理 → 执行反馈 → 终态/待人工处理。

普通编辑立即生效于草稿；产生运动、切换地图、恢复携物任务时提供一次具体确认，显示机器人、目标、地图版本、控制来源及影响。后端必须再次验证，不能把 UI 勾选当安全门。

拟新增统一请求头：schema_version、robot_id、command_id、expected_boot_id、expected_revision、control_lease_id；业务对象另带 task_id/map_id/map_version/location_version。响应包含 accepted、operation_id、state、revision、reason_code、message、retryable、human_required。任务 ID 与 Action goal UUID 分开。

- 同 command_id 同内容：返回同一操作当前结果，不重复动作；同 ID 不同内容拒绝。
- 响应超时：显示“结果未知”，查询 operation/command，不自动生成新 ID 重做。
- 取消：显示“取消请求中 → 等待动作终态 → 已取消”；停稳另显示独立观测结果。
- 旧 boot/revision 的消息不能覆盖新事实；重连先获取快照，再订阅增量。
- 控制者退出、窗口关闭不能被误认为任务已取消。
- 当前循环服务仍使用 request_id/expected_boot_id；通过适配器映射，不立即破坏现有接口。

### 2.2 状态分层

| 层次 | 拟冻结状态 | UI 含义 |
| --- | --- | --- |
| 连接 | DISCONNECTED / SYNCING / ONLINE / STALE | 是否有可信的新鲜事实 |
| 控制 | OBSERVER / LOCAL / WCS / TAKEOVER_PENDING | 谁允许提交操作 |
| 业务任务 | ACCEPTED / RUNNING / PAUSING / PAUSED / CANCELING / SUCCEEDED / CANCELED / FAILED / RECOVERY_REQUIRED | 任务生命周期 |
| 动作阶段 | 导航、感知、抓取、运输姿态、放置、地图切换等 | 当前做什么，与任务状态分开 |
| 数据质量 | VALID / STALE / UNKNOWN / CONFLICT | 数值能否用于决策 |

按需把既有节点状态映射成上述视图，保留原始状态和原因。例如循环执行器 CANCEL_UNCONFIRMED 显示“取消未确认，禁止新路线”，不能映射为已取消。恢复操作只在后端明确可恢复的检查点提供。

建议稳定错误码采用领域字符串，界面文案可变：CONTROL.NOT_OWNER、STATE.STALE、REQUEST.BOOT_MISMATCH、REQUEST.CONFLICT、NAV.GOAL_REJECTED、NAV.PREEMPTED、NAV.CANCEL_UNCONFIRMED、MAP.SAVE_FAILED、MAP.VERSION_MISMATCH、MAP.LOCALIZATION_UNCONFIRMED、ARM.PLAN_STALE、CARGO.UNKNOWN、RECORDING.PARTIAL、RECOVERY.REQUIRED。错误同时标明可重试动作；不能对所有错误提供同一个“重试”。

### 2.3 控制归属

新增 C++ 控制会话后端管理租约，实际执行入口校验租约与请求；仅在 UI 隐藏按钮不能阻止其他 ROS 客户端。网络身份与 DDS 权限由部署配套，租约 ID 本身不是身份认证。

保留已有 operator > route > exploration 仲裁。人工接管需后端冻结自动调度、确认当前动作终态后移交；机械臂/携物阶段不能简单套导航抢占。租约过期阻止新命令、请求受控暂停，无法确认时进入待人工处理；具体保持/停车由设备适配层决定，不自动回 Home 或松爪。

## 3. P0：接口、状态、错误码与假后端

交付：接口清单及版本规则、能力查询、统一状态快照、结构化事件、C++ 假后端、场景用例及兼容适配。

实施顺序：
1. 清点当前服务/Action/Topic 与唯一控制拥有者，标记已用、拟建和废弃入口。
2. 在 astribot_operator_msgs 扩展强类型协议；先冻结导航、探索、地图、记录契约，机械臂/WCS 可版本化扩展。
3. 新增 astribot_operator_backend C++ 包，集中适配既有入口、控制租约、命令幂等与能力查询；不复制导航算法。
4. 新增 astribot_operator_test_support C++ 假后端，支持延迟、拒绝、取消失败、乱序、断线、重启、缺参数和存图失败。测试专用命名空间及域，不连接设备。
5. UI 与假后端跑契约测试，再逐项换真实适配器。

验收：相同命令重复 100 次只产生一次动作；旧实例请求拒绝；超时不误报失败或成功；能力缺失/状态过期禁止提交。已存在的循环导航 boot_id/幂等机制复用，不能据此宣称全系统协议已经冻结。

## 4. P1：最小可用导航与建图工作站

### 4.1 操作逻辑

| 功能 | 用户流程 | 完成/失败反馈 |
| --- | --- | --- |
| 单点导航 | 地图按下拖动朝向 → 预览目标与坐标系 → 确认 → operator 仲裁 | 展示受理、执行来源、到位终态；被抢占独立说明 |
| 多点循环 | 连续选点 → 排序/删除/保存 → 设置停留 → 确认 → 1…N 循环 | 当前点/圈数；失败停止；取消仅作用于本路线 |
| 取消 | 选择任务/路线 → 取消 → 等待终态 | ACK 不等于完成；未确认时禁止重启冲突任务 |
| 探索 | 校验建图模式与资源 → 开始 → 暂停/恢复或结束保存 | 现有 pause/resume/cancel 可复用；“开始新会话”需新增后端能力，不能用 resume 伪装 |
| 日志 | 查看实际目录 → 录制/标记/参数快照 → 打开故障 | 区分全栈 session.log 与当前诊断包，关联会话后统一入口 |

探索无候选点只是评估条件，不应由 Panel 判断建图完成。完成决策来自探索后端，需区分地图未就绪、暂不可达、预算耗尽与满足完成条件。已有 finalization 接口保留：完成保存标 COMPLETED，主动取消保存标 CANCELED_PARTIAL；暂停不结束会话。等待导航终态和停稳 → SLAM 收尾 → 校验资产 → 提交会话 → 显示 SAVED。保存失败保留错误与目录，开放 retry；SAVED 与“建图覆盖质量达标”分别展示。

### 4.2 落地与回放

复用 OperatorPanel、LoopRoutePanel、RoutePointTool、route_executor、mapping_session_node 和 diagnostics_recorder。先补总览与能力门控，再接统一后端；既有入口迁移期间保持单一路径，不允许新旧后端重复提交。

最小回放继续提供事件与参数回看；补充只读 TF/地图/路径/里程计播放、暂停、倍率和事件跳转。参数同时显示 requested/observed/effective/unknown，实际未有 effective 证据时明确未知。回放只发布显示白名单数据到隔离域，不回放控制 service/action；历史速度作为证据显示。

验收：完整“选点—执行—取消”“循环—失败/取消”“探索—完成/取消—保存/重试”假后端与仿真测试；回放无法触发机器人动作；缺 TF/参数有缺口提示。建议目标：GUI 响应 p95 ≤100 ms，LAN 受理响应 p95 ≤300 ms，1 Hz 状态连续 3 s 无更新显示过期；均需实测，不是当前成绩。

## 5. P2：地图会话、工位与人工换层

新增 astribot_map_manager C++ 包管理资产和事务；包装现有 Voxel SLAM 会话，不默认替换 SLAM/定位栈。面板只调用后端，不自行拷贝文件切地图。

- 地图卡片：ID、不可变版本、楼层、预览、保存原因、文件完整性、定位兼容性。SAVED 资产通过校验后才可激活；工作草稿与发布版本分离。
- 工位编辑：选择地图版本 → 点击站位及朝向 → 填用途/名称 → 校验 → 保存新版本。机械臂作业目标与底盘停靠位分别存储。已有任务引用的版本不被原地覆盖。
- 地图切换：停止新任务 → 等待动作终态/停稳 → 保存旧会话事实 → 加载新会话 → 确认定位/TF/地图及代价地图一致 → 提交 active_map_version → 废弃旧路径。
- 人工换层向导：导航至交接位 → 确认运输状态 → 等待人工转运 → 操作员确认已到目标楼层 → 加载与重定位 → 验证 → 继续。记录操作者、时间、事务 ID；不得用一个“换层成功”按钮跳过定位验证。
- 换层失败保持阻塞态。已被人工移到新楼层后，回滚旧地图不代表可以恢复运动。轮式平台不将楼梯视为导航连接。

长操作拟用 SaveMapSession/SwitchMapSession Action，工位用查询/版本提交服务。事务持久化 INTENT、各步结果与 COMMITTED；进程重启发现未提交事务则 RECOVERY_REQUIRED。

诊断增加自动故障前后窗口（建议前 30 s/后 20 s，实际覆盖必须展示）、地图资产哈希、工位版本和切换事件；按字节预算配置，不保证缓存一定达到目标时间。

验收：损坏资产、旧版本工位、定位失败、重复人工确认、事务中断后重启均不得误提交；成功切换后旧路线失效。跳转回放需重建静态 TF、地图、增量状态和参数检查点，并验证与顺序播放一致。

## 6. P3：机械臂技能与抓放反馈

复用现有 astribot_transport_msgs/PlanManipulation 规划接口，先核对现有执行适配能力再扩展，不从“存在规划 Action”推断已能安全实机抓放。

交互：选择左右臂/技能和对象 → 展示目标、坐标系及识别有效期 → 请求规划 → RViz 轨迹/碰撞场景预览 → 后端再次校验 → 确认执行 → 分阶段反馈 → 更新载荷证据。

规划结果绑定 plan_id、scene_revision、map_version、起始关节状态、载荷和有效期；任一条件失效必须重新规划。执行适配器负责关节/夹爪接口、超时、终止与反馈，UI 不调用 SDK。

载荷状态：EMPTY / GRASPING / HELD_CONFIRMED / PLACING / UNKNOWN。夹爪命令成功不是抓取成功；夹爪电流、开度、视觉等证据按具体硬件标定。空载 Home 与带货运输姿态分开；只有确认运输姿态及包络后才开放带货导航。故障取消不默认松爪或回 Home。

诊断记录场景版本、标定、目标及置信度、轨迹摘要、关节/夹爪反馈、持物判定与参数。验收按规划预览 → 假执行 → 仿真 → 受控单臂实机 → 双臂干涉场景推进，证据分开。

## 7. P4：单房间搬运、队列、WCS 与恢复

新增/复用 C++ transport_task_manager 负责持久化业务状态机；名称在 P0 清点后确定，避免再建一个重复总调度器。WCS 网关单独包，仅做协议、身份、去重与状态投递，不实现机械臂动作序列。

用户选择同一地图版本的货架与目标工位、零件、载荷策略 → 前置检查 → 提交队列 → 后端逐阶段执行。自动任务走 route 仲裁。流程：PRECHECK → NAV_PICK → PERCEIVE_PICK → PICK → TRANSPORT_READY → NAV_PLACE → PERCEIVE_PLACE → PLACE → VERIFY_EMPTY → REPORT。

队列仅允许改动未执行任务；暂停请求在当前动作可安全暂停处生效，否则显示 PAUSING；取消导航任务和取消已抓货任务分别处理，后者需要安全保持/人工处置。任务取消不等于物料交接完成。

WCS 以外部 task_id/幂等键去重；接单 ACK 与完成报告分离。持久化命令意图、阶段结果和待投递报告，重连后重发状态、查询任务事实，不能重新抓取。网络不承诺“恰好一次”，用去重和实物确认实现业务一致性。

重启恢复：列出未完成任务 → 查询设备/载荷/位置/动作事实 → 展示“已确认、未知、可恢复检查点” → 人工或后端策略确认 → 从批准阶段继续。ACK 丢失、动作成功但结果未持久化等情况保持 UNKNOWN，不能盲重试抓放。

验收：固定工位单房间先闭环；WCS 重复下发/断连/重启、各阶段断点、物料未知、人工抢占均有确定处理。故障工单包含任务、地图/软件/参数版本和回放入口。

## 8. P5：动态工位、跨楼层与现场验收

P2 完成事务机制，P5 验证整机携物跨楼层业务；自动电梯对接另立范围，首版保持人工辅助。

动态工位：检测候选 → 展示位置/置信度/时间 → 可达性与场景校验 → 固化本任务目标版本 → 执行前复核。目标失效重新识别，不能让旧视觉结果驱动抓取。

按空载/额定及边界载荷、窄通道、人员/障碍、定位退化、低电、断网、设备超时、磁盘满和进程重启建立矩阵。具体载荷、误差、停距、允许恢复条件由硬件与现场风险评估冻结；不沿用提案中的固定距离当作已验证安全指标。

交付现场操作手册、版本化场景库、验收报告、日志保留/导出策略、升级回归清单。建议记录成功率、成功/失败分组到位误差、任务时长 p95、取消终态时间、物料误判、记录资源开销和缺失数据；明确样本量与测量来源。SLAM 相对误差、仿真真值不代替外部物理测量。

## 9. 包边界、推进顺序与当前差距

以下“当前差距”为初始设计快照；最新施工状态与剩余验收以 [任务状态与关节跟踪问题修复](TRACKING_FIX_AND_TASK_STATUS_20260919.md) 和 [异常验证矩阵](P0_P5_EXCEPTION_VALIDATION_MATRIX_20260919.md) 为准。

| 包/职责 | 处理方式 |
| --- | --- |
| astribot_operator_station | 保留 C++/Qt Panel；逐页拆类，共享状态模型，GUI 不持有权威任务 |
| astribot_operator_msgs | 逐步统一协议，现有循环服务保持兼容迁移 |
| astribot_operator_backend（拟新增） | 能力、控制归属、命令验证、旧接口适配；不重复业务任务机 |
| astribot_route_executor | 保留循环运行与子导航目标所有权 |
| astribot_s1_exploration/mapping_session_node | 保留探索结束收尾；新地图管理器管理资产和跨会话事务 |
| astribot_map_manager（拟新增） | 地图/工位版本与换层事务 |
| 机械臂执行适配/transport_task_manager（规划项） | 先盘点复用，再补生产执行和搬运持久化 |
| 诊断记录与回放 | 先复用 recorder/evidence，3D 播放独立进程；职责稳定后再拆包 |

当前已核对存在：导航/探索控制 Panel、循环路线、地图 finalization、日志与关键参数事件采集、离线事件参数回看、机械臂规划消息。尚不具备完整 P1 验收证据；控制租约、生产统一错误码、地图工位事务、完整 3D 回放与恢复闭环均按待建设处理。

建议工单顺序：P0 接口矩阵/状态与错误码 → 假后端故障场景 → P1 总览及统一控制适配 → 探索建图完整会话交互 → 只读 3D 回放与资源验收 → P2 地图/工位及换层事务 → P3 规划和执行闭环 → P4 单房间及 WCS 恢复 → P5 现场验收。可在同阶段并行开发 UI 与适配器，但每阶段通过门槛后再开放下一阶段生产按钮。

每张工单必须附：入口/前置条件、状态转换、取消与重启语义、错误码、记录字段、假后端测试、仿真/真机验收边界。实施交付与验收交付分别标记，不用“代码编译通过”代替业务交付。
