# 全窗口任务推进规则

依据：用户 2026-09-23 要求“同步全部窗口，若一个问题排查超一个小时则先记录下来，先过下一个任务。直到所有任务完成，然后逐个破解难点。”本规则适用于本项目全部窗口，优先于历史 90 分钟暂停规则。

## 执行方法

1. 开始下一项任务前，简短复核目标、真实输入、控制权、数据时效/版本、边界条件、失败恢复及验收证据。只推进前置条件已满足的任务。
2. 每个问题分配稳定标识，记录首次开始时间、各次实际排查区间、累计耗时及当前负责人。一次排查达到 60 分钟时完成有界安全收尾并暂缓；不得以换窗口、改名或重新打开任务清零。历史时间无法确定时明确“未知”，不得默认零。
3. 超时记录必须包含：现象/复现入口、已确认事实与假设、尝试和结果、源码/环境版本、日志路径、影响的验收项、下一步最小实验及恢复所需资源。下载或其他外部等待单列，不空等占住整条任务链。
4. 将问题标为 `deferred`；直接依赖它的任务标为 `blocked_by`。独立任务继续施工与验证。暂缓不等于放行，不改变安全阈值、资源所有权或验收标准。
5. 第一轮推进所有可独立完成的任务后，再按安全影响、依赖阻塞范围和证据充分度，逐项重开难点。保留原始累计耗时，每轮仍有 60 分钟检查点；同轮无新证据不重复空跑。确无可执行路径时如实报告外部阻塞，不宣称全部完成。
6. 各窗口只更新自己负责的证据和阶段状态；共同难点清单由搬运仿真窗口汇总。仿真与 GPU 继续明确独占交接，不因赶进度并发抢占。已验证结果保留 Git 记录，未验收候选及失败证据不得当废弃内容清除。
