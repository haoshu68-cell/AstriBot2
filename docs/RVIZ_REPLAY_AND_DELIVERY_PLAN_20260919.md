# 上位机故障记录、关键参数回放与分阶段落地

日期：2026-09-19。状态：设计方案，尚未实现或进行录制/回放测试。补充 RVIZ_OPERATOR_STATION_DESIGN_20260919.md；不修改 SLAM 代码或注释。

## 1. 定位目标

采用移动机器人常见的问题定位思路：轨迹回看、任务分段、异常前后窗口、配置对比、同类故障聚合。这里借鉴扫地机/割草机的问题类别，不声称使用任何厂商私有诊断实现。

| 问题类别 | 本项目对应表现 | 必需证据 |
| --- | --- | --- |
| 卡住/反复脱困 | 底盘不动、保护持续 HOLD、目标反复重试 | 各级速度指令与实测速度、保护原因、近场障碍、足迹/载荷、任务阶段 |
| 漏扫/漏割/重复覆盖 | 探索漏区、重复选择前沿、提前完成 | 地图版本、未知格/可达前沿、候选拒绝原因、访问/冷却记录、完成判据 |
| 越界/贴边异常 | 进入禁行区、窄通道误拒/擦碰风险 | 区域版本、地图原点、TF、代价地图、规划/执行路径、包络及裕量 |
| 定位跳变/地图错位 | 路径突变、地图漂移、换图后目标错误 | TF/里程计/定位状态、地图会话、时间轴、定位模式与有效参数 |
| 原地打转/终点振荡 | 对齐反复、到点不结束 | 控制阶段、误差、指令/实测速度、容差、停稳/惯性参数 |
| 回充失败类问题 | 本项目对应回待机位、低电任务中止；无自动充电对接 | 电量有效性、任务能耗预算、目标/路径、故障与人工确认 |
| 抓放失败 | 抓空、滑落、放置未释放、臂轨迹中止 | 图像/物体位姿、标定、规划场景、关节/夹爪反馈、持物判断和参数 |

诊断输出区分“观测事实”“规则命中的疑似原因”“缺失证据”，不能把规则结论自动当根因。

## 2. 三种回放能力

1. 证据回看：离线读取事件、日志、曲线、参数和 RViz 场景。默认模式，不启动控制算法。
2. 算法重算：隔离环境把历史输入送给选定版本算法，输出写到 replay 命名空间；用于比较结果，不执行设备命令。
3. 仿真复现：把故障条件重建为 Gazebo 场景，用回归脚本验证修改。历史数据回放不是闭环仿真，新算法输出不会改变已录输入；不能宣称逐帧确定性复现。

录到的 cmd_vel、关节轨迹、夹爪命令只作为证据显示；播放策略禁止发布到生产控制入口。ROS action 状态/反馈 Topic 不能完整还原请求、取消和响应，须在业务适配器记录独立事件。Humble 首版不依赖较新 ROS 版本的 service/action 自动录放能力。

## 3. 记录架构

Orin：诊断采集器 + 参数快照器 + 事件触发器 → 故障包。
工作站：索引/分析服务 + ReplayPanel + RViz 回放专用配置。

新增 astribot_diagnostics_recorder、astribot_replay、astribot_diagnostics_msgs；复用 astribot_logging、explore_metrics 及现有采集分析脚本。GUI 与记录器解耦，关闭界面不停止记录。

已有 tools/robot/robot_metrics_session.sh 具备 bag 和 metrics 目录、TF/odom/速度/路径/代价地图/action 状态采集，是迁移起点；其话题表须按当前版本清点，不能原样认定完整。现有录制视频可辅助观察，不能代替带时间戳的原始传感数据。

### 分层数据

- 常驻低带宽：任务/动作生命周期、状态迁移、保护原因、错误、参数变更、速度及里程计摘要、有效性与资源指标。
- 按任务记录：TF/静态 TF、关节状态、路径、地图/代价地图关键帧及更新、机器人包络、定位与控制状态。
- 故障窗口：点云、图像/深度、详细控制量、规划场景变化；按配置限流。
- 版本快照：代码 commit + dirty 补丁或部署文件摘要、构建/依赖版本、URDF/SRDF、标定、地图会话与工位、参数、启动实参、DDS/QoS 配置。

默认建议故障前 30 s、后 20 s，可按任务调整。本机 Humble CLI 已确认 snapshot-mode/max-cache-size、bag 按大小/时间切分；缓存按字节限制，不能保证精确 30 s。后触发窗口由编排器持续录制并封装，不把一次 snapshot 当成完整前后窗口。P0 测实际吞吐再定预算；高带宽用分段滚动文件保留，或降采样后缓存。例如 20 MB/s 的输入仅前 30 s 就需约 600 MB，不盲目占用 Orin 内存。

触发：任务失败、持续无进展、定位失效/跳变、保护原因长时间不解除、控制超时、抓取不确定、通信租约超时、参数应用失败、人工打点。带去抖、冷却和相关故障合并；按 robot/task/episode 聚合，保留首因与后续症状。

## 4. 关键参数记录：必须交付的能力

### 4.1 参数清单

| 类别 | 记录内容 |
| --- | --- |
| 导航规划 | 规划器/控制器插件与版本、运动模型、速度/加速度/jerk 约束、采样/预测时域、代价权重、允许倒车 |
| 到点与跟踪 | xy/yaw 容差、驻留、停稳速度、阶段超时、接近限速、惯性补偿、滑移/偏差约束 |
| 代价地图/保护 | 分辨率、更新率、膨胀参数、障碍范围/高度、footprint、载荷包络、窄通道裕量、传感超时、保护区域 |
| 探索 | 前沿/采样阈值、代价权重、可达性条件、候选比较预算、失败/冷却预算、完成确认条件 |
| 定位建图 | 当前后端、mapping/localization 模式、地图/会话版本、frame、外参及相关有效参数；仅通过现有只读接口采集 |
| 双臂/夹爪 | 规划组、规划器、速度/加速度缩放、碰撞/奇异阈值、运输姿态、夹爪张开度/力限及 force_applied |
| 视觉 | 模型/权重摘要、置信度、相机内参/手眼外参、深度尺度、曝光/同步配置、位姿有效期 |
| 任务/系统 | 超时、重试、低电阈值、控制租约、QoS、use_sim_time、frame、namespace、域、设备固件和 SDK 版本 |

有些值来自动态消息、SDK、设备或模型文件而非 ROS parameter：例如 footprint、RobotEnvelope、夹爪实际力限。分别记录其来源及确认状态，不伪装成 ROS 参数。未能读取的实际值标为 unknown，不能用 YAML 默认值填成“已生效”。

### 4.2 四类配置事实

1. requested：YAML、launch overrides、操作员请求和命令 ID。
2. accepted：节点参数回调/服务是否接受请求。
3. observed：GetParameters 回读值、设备反馈或节点报告的值。
4. effective：算法确认应用的配置修订号和时间；如果没有确认接口，只能标 observed，不能断言该控制周期已使用。

启动时从节点服务读取参数值、类型、描述符/约束，配置文件单独存档。节点每次重启创建 node_instance_id，重新快照。跨节点不存在天然原子快照，记录各节点采样区间；配置过程中运动任务应按后端事务规则限制。

订阅 /parameter_events 只作为增量来源，补周期校验及重连重采样。覆盖参数新增、修改、删除；事件丢失或来源不明时标记配置历史缺口。SDK/环境变量/硬编码常量没有参数事件，以版本化 manifest、适配器反馈补足。首版对关键节点前后两次读取检查稳定性；不稳定则重试或标不一致，不能伪造同一时刻全局快照。

每条变更保存 robot_id/session_id/task_id、node_fqn、node_instance_id、参数名/类型、old/requested/accepted/observed、来源、操作者/command_id（未知则留空）、revision、应用结果、UTC/ROS/本机单调时间及时间段编号。单调时间只在同机同启动内比较；跨机使用同步估计及误差范围。

### 4.3 回放时的表现

- 点击时间线任意时刻，显示该时刻参数值及来源/有效性；与当前值、上一故障包并排比较。
- 修改参数显示时间线标记，可一键跳到修改前后比较轨迹、速度和保护原因。
- 参数文件/模型/地图摘要不匹配时明确提示，禁止静默加载当前配置替代历史配置。
- 证据回放不应用参数；算法重算仅向隔离节点应用快照，回读验证后开始，输出包记录参数差异。
- 对事件缺口、未确认生效区间显示未知；不跨越缺口推断参数持续有效。

## 5. 故障包与存储

```text
incident_<UTC>_<UUID>/
  manifest.json                 # 版本、身份、时段、完整性、关联任务、文件 SHA-256
  session.log                   # spdlog 相关区间，保留原会话索引
  events.jsonl                  # 业务/保护/操作/录制质量事件
  parameters/initial.json
  parameters/changes.jsonl
  parameters/checkpoints/       # 分节点快照及配置一致性状态
  config/                       # YAML、launch、模型/标定摘要和必要文件
  maps/                         # 地图/工位版本；大文件可指向内容寻址资产
  bag/                          # rosbag2 数据与 metadata
  metrics/                      # 速度、误差、覆盖、TF 年龄、数据丢失统计
  report.json                   # 事实、疑似原因、缺失证据
```

内容寻址资源必须在引用存续期保留；导出给现场支持时选择自包含导出并验证无悬空引用。导出前脱敏图像、位置、主机/账号和密钥；不整份复制环境变量。加密/访问策略按现场权限执行。

设置总容量、最小剩余空间、任务/故障优先级；优先清理未锁定的普通记录。待分析故障和验收包可 pin，配额耗尽时报警并降级高带宽采集；不能因写日志阻塞控制或磁盘满而无限重试。临时包写完原子提交，异常退出保留 partial 标记，不显示为完整包。校验覆盖 bag 可读性、时间范围、预期话题、消息数/间隙、关键参数和配置资产，而不只是文件是否存在。

## 6. ReplayPanel 与回放隔离

界面：左侧故障列表（任务/地图/版本/错误筛选），中央 RViz/相机，底部事件时间线和曲线，右侧关键参数及证据面板。支持播放/暂停、倍率、事件跳转、指定时间定位、标记区间和导出。单步定义为下一条事件/消息；不假设多传感器具有同一“帧”。

维护独立 LIVE/REPLAY 进程或窗口，醒目标识模式、机器人和会话。回放使用独立 DDS domain 与隔离网络/容器，不运行厂家 SDK/驱动，不挂载硬件设备、不连接生产网关；白名单发布到回放主题。ROS_DOMAIN_ID 单独不构成安全边界。

所有历史运动命令映射为证据主题；不回放 service/action 执行请求。静态 TF、机器人模型、地图关键帧、增量代价地图和参数检查点在跳转前重建；不能从任意时间直接播增量。向后跳转须重置 RViz TF/缓存、算法内部状态与时间段，再从检查点预热，避免未来数据污染过去。

真实运行记录按 bag 时间驱动唯一 /clock；仿真记录须保存原 /clock，停顿/回拨拆成独立时段，选择一种时钟权威，禁止播放器与录制 /clock 同时发布。时间线同时显示源时间与接收时间；无同步证据不能声称跨机毫秒级对齐。

本机已确认 Humble 支持 rate、start-paused、start-offset、clock、topics 和 remap。任意 seek/单步的服务或 API 必须在 P0 核对；不能照搬 Rolling 文档。缺少功能时由受控重启播放器、索引跳转和检查点恢复实现。当前列出的存储插件含 sqlite3，首版采用它；MCAP 作为另行安装与性能验证项。

| 接口 | 类型 | 语义 |
| --- | --- | --- |
| /diagnostics/mark_incident | Service | 人工打点，返回 incident_id；不表示故障包已落盘 |

| /diagnostics/export_incident | Action | 校验、脱敏、自包含打包，反馈进度与最终摘要 |

## 8. 分阶段具体落地

以下按依赖顺序推进，不承诺未经团队人数和数据吞吐评估的工期。

### P0：契约与采集基线

- 清点当前话题/服务/节点、frame、QoS、参数来源、关键控制链；为话题清单建立 profile：nav、exploration、manipulation、vision。
- 固定事件 schema、参数快照 schema、故障包 manifest、版本/时间/幂等规范。
- 完成 Humble 能力探测，sqlite3 吞吐与 Orin CPU/内存/磁盘预算；核对启动覆盖参数与节点回读差异。
- 交付：接口字典、录制配置、参数白名单、假数据故障包、预算报告。
- 验收：缺失节点/参数标未知；参数类型保真；模板包可校验；时间回拨和跨机时钟误差能表达。

### P1：导航运维台 + 参数记录 + 最小回放

- 落地 OperatorPanel 总览、仲裁导航/取消、状态/日志；记录器常驻保存事件、参数初始快照与变更、TF/odom/路径/指令。
- ReplayPanel 支持打开故障包、轨迹/路径回看、事件定位、速度曲线、按时刻参数查询；默认只读隔离。
- 为既有 runs/metrics 提供 legacy 导入：可显示已有数据，缺失参数/版本明确标缺失，不能倒填历史值。
- 交付：可安装插件、记录/回放后端、默认 profile、导出包和自动化测试。
- 验收：重复命令不重复执行；参数先后修改及节点重启可正确还原；断线重连标出缺口；回放无生产控制出口；录像缺失不影响事件/参数查询。

### P2：地图探索诊断 + 自动故障窗口

- 接入地图会话/工位事务；记录候选/拒绝原因、可达/未知统计、保护状态、地图版本和足迹。
- 自动触发无进展、定位失效、重复重试、提前完成疑似案例；实现前后窗口、去抖合并、磁盘配额、pin。
- 新增探索轨迹热图/访问次数、目标选择序列、未覆盖区域叠加；覆盖指标只针对给定地图与可达区域，不混同扫地机清洁覆盖率。
- 验收：模拟故障前后数据覆盖满足预算，无法满足时可观测；晚加入能恢复静态 TF/地图；跳转与连续播放的状态一致；坏地图/错版本显式拒绝。

### P3：机械臂视觉回放 + 抓放技能台

- 同步记录关节、夹爪、规划场景、轨迹、物体位姿、图像/深度、标定及规划参数；记录夹爪力限是否真正应用。
- 增加抓取前/接触/抬升/运输/释放阶段标记；显示期望与实际、物体相对末端运动和持物证据。
- 真机执行能力在原规划接口之外单独交付，并受同一任务后端控制。
- 验收：抓空/滑落/放置失败可定位到证据；相机时间错位、缺帧、标定版本不匹配均有提示；运动命令始终只读回放。

### P4：搬运闭环 + 可复现问题工单

- 集成任务队列、WCS、持久化恢复；任务失败自动生成工单，关联 incident_id、业务任务、软件/参数/地图版本。
- 同类故障聚合，A/B 展示轨迹、误差、耗时、保护占比、参数差异；提供隔离算法重算与选定场景仿真复现。
- 验收：RViz 退出/后端重启/网络中断不丢业务事实；旧版本证据可打开；参数差异有追溯；重算结果标明非闭环真机结果。

### P5：现场回归库与规模化运维

- 固化窄通道、终点振荡、定位跳变、低电、抓放不确定、人工换层等基准故障集，纳入离线回归。
- 多机汇总、带宽/保留策略、访问审计、升级前后指标对比；参数只允许审核后应用，禁止回放包自动写回真机。
- 验收：版本升级跑基准集；硬件负载下完成长稳与资源测试；断电/磁盘满/包损坏场景能保留明确的 partial/unknown 状态。

## 9. 初始量化目标（待 P0 实测校准）

- 关键参数记录覆盖率：清单内 100% 有值或明确失败原因，不允许静默缺失。
- 构造 100 次参数变更与 10 次节点重启用例，历史查询结果与事件顺序一致；缺口时结果为不确定。
- 故障包 100% 带版本、时间域、文件哈希、话题质量和参数完整性状态。
- 控制事件不因高带宽图像积压；记录器额外 CPU 平均预算先定总算力 10%、内存 512 MiB，压力测试超限则降低 profile，并评估控制周期 p99 延迟变化，不能只看 CPU 平均数。
- 默认 30 s 前/20 s 后作为目标，实际覆盖时段随包报告；丢失、缓存不足和写盘失败必须可见。
- 代表性故障包热索引事件跳转 p95 < 2 s；算法重算预热单独显示，不计为已经到达目标时刻。
- 隔离验收：回放对生产导航、底盘、夹爪和机械臂控制接口发布/调用次数为 0，通过拓扑检查和测试接收器验证。

## 10. 依据与边界

## 11. 实施约束与本轮进展

用户确认新增功能以 ROS2 功能包承载、优先 C++，不继续扩散采集脚本。最小上位机必须有控制接口，不能只有只读监控。

首批代码位于 `ws_robot/src/astribot_operator_station`：C++ RViz Panel、独立 C++ rosbag2 采集器、C++ 离线查询工具、XML launch。此包先收拢 P0/P1 基础能力，后续按职责稳定情况拆成独立包，不为每个按钮创建脚本。

已接入：operator 导航提交/本目标取消、探索暂停/恢复、采集启停/故障打点/参数快照、离线事件逐条/顺序播放和参数状态查询。保留 Nav2 仲裁和原有控制链；不发布速度。

参数记录使用明确白名单、逐项读取（兼容 Humble 未声明参数导致批量请求失败的情况）、参数变更订阅和周期回读；类型保真，非有限浮点显式编码，读取超时/变更重叠标 unknown。尚无节点 boot identity 或算法 effective revision，不能称为完整 P1 配置重建验收。

当前回放是本地 JSON 事件与参数证据浏览，不发布 ROS 消息；bag 已记录但 3D 时间同步回放尚未实现。后端鉴权租约、地图事务、通用搬运启动、真机抓放和参数写入尚未接入，界面明确标示。原有采集脚本暂不删除，待功能/话题覆盖和资源验收等价后再退役。
