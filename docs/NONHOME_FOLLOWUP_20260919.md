证据目录：`runs/nonhome_followup_20260919/`。本轮仅使用导航仓库的隔离实例
`nonhome_followup_20260919`，ROS Domain 74、Ignition partition
`astribot_nonhome_followup_20260919`、发现端口 18148/18149。真机未连接。
源代码工作区由多个任务共享，构建与运行证据使用独立目录。

## 后续实现语言约定

按用户要求，后续新增规划、几何、碰撞、安全守卫、状态机与 ROS 数据处理节点优先 C++。
Python 用于 launch、环境编排、测试、故障注入与数据分析。现有 Python 任务层暂保留
必要的协议绑定及缺陷修复；迁移按模块逐项对照验证，不在本轮整体重写或改变控制权。

本轮执行守卫 `astribot_s1_transport_mtc/execution_guard` 已用 C++ 实现。
`SetExecutionGuard` 请求携带操作上下文、关节集合与 map 下的底盘参考位姿；
`ExecutionGuardStatus` 回传上下文、源时间、健康状态、最大关节误差和底盘偏移。
仅当上下文相符、守卫激活、采样与接收时间有效时允许继续执行。

守卫覆盖 fixed_v2 下的 MTC ARM 段：关节目标/实测误差超过 0.05 rad、
底盘移动超过 0.02 m / 0.02 rad、关节或 TF 证据超过 300 ms、时钟回跳等故障锁存。
50 Hz 墙钟检查，状态中的源时间不被心跳延长。它不直接发布电机命令；
任务通过原执行器取消并保留载荷。旧准备动作、夹爪和任务进程失联的独立停车仍不在此守卫覆盖内。

## 本轮改动

- C++ ArrivalController 在通道终端进入零指令制动后，等待原有 0.6 s 新鲜测量
  停稳窗口再判定。保持原 2 mm / 0.1° 硬容差、停止距离预算和通道内禁原地转向；
  停稳后仍超界则明确拒绝，不用更宽容差换成功。
- C++ Gazebo 载荷插件增加同一物理步的实际位姿、目标位姿与步长证据。
  分析脚本将物理跟随误差与 TF 采样误差分开，等待有界的采集时刻 TF，禁止外推。
- fixed_v2 仿真的 robot_state_publisher 从 20 Hz 提至 100 Hz；旧模式仍为 20 Hz。
  该变更不是相机外参标定或真机精度证明。
- MTC launch 显式提供速度/加速度缩放参数，默认仍为 0.1；本轮另测 0.03。
- 任务绑定在动作受理和执行等待期间检查守卫；即使 future 已完成仍检查最终状态。
  取消失败保留原始故障、待受理句柄和执行器占用，不能被 WAIT_TIMEOUT 覆盖。
  未确认执行结束时不解除 C++ 守卫。账本记录取消请求、响应和终态。

## 已发现的问题及证据边界

`transport01` 在生成搬运姿态过程中出现关节偏差和底盘移动，随后首段导航被
PATH_QUALITY_UNSAFE 拒绝。不能将该拒绝算作规划器误报。
本次实际执行的旧/新 MTC 二进制都使用 0.1 缩放，没有证据支持“旧程序未限速”的解释。

`transport02` 使用初始 Python 守卫时在 PREGRASP 检测到 0.050621 rad 跟踪偏差。
此实现已替换为 C++，该记录仅为历史故障证据。

`transport03` 使用 C++ 守卫和 0.03 缩放。守卫在 TRANSPORT_POSTURE 阶段
以关节 3 误差 0.053960 rad 锁存，但 MoveIt 继续执行，任务最终记录 WAIT_TIMEOUT。
随后实测关节 3 长时间停在 3.1 rad 上限，而轨迹目标持续减小；底层关节/接触原因尚未证实。
故障后载荷保持 ATTACHED，不能自动重复抓取或宣称完整搬运成功。

已核对本机 MoveIt 2.5.9 对应的
[上游执行 capability](https://github.com/moveit/moveit2/blob/2.5.9/moveit_ros/move_group/src/default_capabilities/execute_trajectory_action_capability.cpp)：
执行回调在独占回调组同步等待轨迹，取消回调无法及时处理。
当前共享仓库另一项工作新增了 C++ `CancellableExecution`；本任务复用、独立构建并验证该插件，
不重复实现、不改写对方源文件。保持 MoveIt trajectory execution manager 为控制器唯一执行入口。
任务绑定对取消错误的掩盖是另一处已修复的问题。动作受理期缺少检查属于此次一并补齐的边界，
不能仅凭上述日志断言它就是 transport03 的触发点。

载荷比较：transport01 的同物理步位置跟随误差最大 3.453 mm，TF 目标与物理目标
最大差 37.220 mm；transport03 使用 100 Hz TF 和更慢轨迹后，后者最大 4.096 mm。
两项配置同时变化，且两次任务均失败，这不是单变量因果试验或全流程验收。
原生物理、ROS 原始采样和缺失记录保存在各 `payloadNN` 目录中。
