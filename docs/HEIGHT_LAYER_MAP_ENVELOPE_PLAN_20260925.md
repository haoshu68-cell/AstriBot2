## 2. 单一高度定义

配置来源：`ws_robot/src/astribot_s1_mapping/config/height_slices.yaml`。

| 层 | 距地面高度（m） | 主要对象 |
|---|---|---|
| low_obstacle | [0.05, 0.25) | 托盘、踏板、低矮物 |
| main_nav | [0.25, 0.68) | 货架立柱、墙体 |
| torso | [0.68, 1.18) | 桌沿、低横梁 |
| head | [1.18, 1.63) | 门楣、悬空横梁 |
| upper_extension | [1.63, 2.30) | 高姿态机械臂、抬高载荷 |

额外上层保留原先覆盖至 base z=2.2 m 的意图；2.30 m 是此静态地图产品的上界，不代表传感器已验证覆盖到该高度。低于0.05和高于2.30的点分别计数，原始三维源保留；包络超过地图有效高度不得按已覆盖放行。

高度参考必须明确：地图高度 `h=z_map-ground_z_map`。不得直接使用世界模型的 spawn_z、轮半径或另一个会话的 ground_z。当前模型审计显示，scene39 平地仿真底盘基准离地约0.095 m；旧切片隐含0.08 m，存在约15 mm差异。该实测关系来自本会话模型碰撞地面与同戳位姿，不能外推到旧SLAM地图、真机或坡道。

本轮旧仓库地图回放使用拟合地面 `ground_z_map=-0.0845156162`，明确标注 `offline_plane_fit_not_calibration_20260925`。其地面语义/绝对高度没有独立真值。分层算法的边界正确性另由已知地面合成夹具验证。

水平地面是当前范围。将来机器人俯仰/侧倾时，应把形体和观测同时变换到同一重力水平坐标系，再切片；仅减去一个z偏置或改frame名称不够。地面/姿态误差须计入垂直交叠区间。

## 3. 地图数据流与实现

```text
已保存 session/manifest.json
  + alidarState.txt（零基scan行号、最终三维位姿）
  + kf/<scan_id>.pcd（局部IMU坐标、未按导航ROI裁高）
       ↓ 校验文件哈希、帧、关键帧集合
C++ height_slice_map_node
       ↓ 对每帧应用完整旋转和平移，再按距地高度分类
独立五层 OccupancyGrid + HeightSliceMaps 原子集合
       ↓
PGM/YAML + manifest.json；当前独立展示/验证，未覆盖原 /map
```

源文件来自当前 SLAM 已有持久化接口。关键帧保存前已有融合/体素平均，不是原始全分辨率点云。`/map_pmap` 先发空消息再分片，不能将其中任一消息当完整地图；`KeyframeSubmap` 当前已提前裁高，不用于此产品。

输出：

- `/height_maps/{low_obstacle,main_nav,torso,head,upper_extension}`：标准 OccupancyGrid，可靠、transient local、depth=1，供RViz/独立地图消费者读取。
- `/height_maps/snapshot`：`astribot_slam_msgs/HeightSliceMaps`，同一条消息携带所有层、共同XY栅格、地图内容哈希、高度配置哈希、ground参考、源点计数。规划消费者以后消费此集合，避免独立话题到达顺序造成混版。
- header 时间是加载/发布快照时间，**不是新的传感器采样时间**。这是不可变静态地图产品，不提供动态障碍新鲜度。
- 每层只输出 `100=端点占据`、`-1=未知`。没有真实射线起点和观察体积，不输出 `0=已观测空闲`。没有任何原有二维free被复制到高层。

同角度桶取最近障碍仍由现有 `SliceProjector` 完成；它是局部扫描产品。独立地图必须保留所有端点，不能先取最近点再生成地图，否则会丢掉同方向更远的货架/墙面。融合扫描也不能拿来清空所有高度层。

## 4. 分层包络数据流

```text
URDF碰撞形体 + 同次关节状态/误差界 + 已确认附着物形状及link坐标
       ↓ 复用 RobotModel::geometry 同次FK
每个形体的保守XY投影及垂直区间（含现有padding/关节误差）
       ↓ 与同一height profile逐层相交
每层凸包 P[k] + 真实总体最高点/最低点 + 模型/关节/载荷来源
```

按用户在协作任务中新增的“不要并存，旧的删掉”要求，旧固定0.25m循环已从C++生产核心删除，仅留档；`RobotGeometry::slices` 改为使用显式高度边界，缺失边界快速失败，无旧算法回退。不能把已有0.25m粗结果再次分桶，也不能把整机总凸包复制五份。形体与层采用闭区间相交，边界形体可同时进入相邻层，这是有意的保守处理；点云分类采用半开区间。空层保留层身份及空多边形，表示完整模型在该区间无形体，不能代表模型缺失。

`geometry_state` 已从同一计算结果输出统一分层，继续绑定 `RobotGeometryState` 的 source/sequence/clock_epoch/model_revision/attachment_revision/逐关节来源和有效期；空层序列化也经过隔离ROS验证。节点通过 `height_profile_path` 读取同一份mapping配置；`ground_in_base_m`可显式给出，当前仿真默认-0.095，非仿真未提供时拒绝启动。该默认只适用于本次审计的平地近水平仿真参考。

旧几何ACK只证明旧二维契约，不能自动充当分层ACK。后续规划快照必须绑定层配置和包络内容摘要，本轮未扩展在线ACK或启用分层规划。旧感知投影的高度参考/覆盖也必须在实际接入前与新profile核对；当前隔离节点验证不能替代整栈覆盖验收。

已获取scene39记录中50.0s、88.0s、104.4s的三组包络，包括带版本的空载快照和已确认附着的transport_box_01。档案仅持久化账本转换事件，没有连续lease心跳，所以结果明确 `runtime_admissible=false`；这些是历史形状重算，不能证明这些时刻在线账本新鲜度。最初以连续心跳假设读取档案时被拒绝，已保留失败记录，随后按实际持久化契约标明证据边界，未改变任何运行时时效门槛。

104.4s运输姿态各层XY尺寸约为0.633×0.633、0.614×0.377、0.567×0.736、0.272×0.736、0.268×0.268m（包含现有几何padding及0.003关节误差界）。保守最高点约1.706m，说明只保留1.63m以下会截掉当前模型上部，额外上层有实际必要。尺寸不是通道所需宽度，转动扫掠及环境余量仍须单独计算。

## 5. 规划耦合算法和当前仓库接入点

对底盘候选位姿 `q=(x,y,theta)`，逐层检查：

`blocked(q) = OR_k intersect(R(theta)·P[k]+(x,y), occupied(M[k]))`。

检查多边形填充区域和障碍格整个面积，不只检查轮廓边。空包络层可跳过，非空包络碰到未知覆盖应报告覆盖不足。所有非空层通过才可认为该位姿已验证；不同层分别给出碰撞格、最小净空和原因。

路径与运动轨迹必须检查相邻采样之间的扫掠区域。保持现有填充多边形碰撞函数的保守采样余量思路，用平移距离与外接半径乘角度变化之和控制采样间隔；对间隔再做位移界膨胀。定位/跟踪/地图误差与关节误差各只计入一次，栅格自身面积已经通过格矩形检查体现，不再机械重复加整格半径。

最小接线顺序：

1. **先做共用 C++ 分层碰撞查询。** 输入不可变地图集合、同配置包络、候选位姿/路径；返回 CLEAR/BLOCKED/UNKNOWN 及具体层/格/版本。规划、路径复核、局部轨迹使用同一个查询核心。
2. **先接路径验证，证明判断正确。** 接入当前 `exact_goal_planner.cpp::collisionIndex`、`path_tracking/check_path` 和 BT 路径准入。可检测已有候选路径的高度碰撞；这一步不能宣称能搜索出新的绕障路径。
3. **再接搜索内部。** 当前主用是封装的 Smac 2D；Hybrid/Lattice在源码中仍要求 `planner_evaluation_only`。原生单张2D costmap + 单footprint不能表达多层轮廓。保留主用规划器作为候选，分层查询验证；若需利用高度差寻找原来被总凸包排除的路线，必须在搜索扩展/运动基元检查中调用同一查询。可按角度预计算每层障碍与对应轮廓的配置空间障碍，再跨层求并；缓存键包含地图、层配置、包络和角度离散版本。不能只在终点验一次或更改footprint后直接宣称支持。
4. **再接局部轨迹。** MPPI新增分层轨迹碰撞约束/critic；预测点和点间扫掠均检查，不能只对最终选中轨迹加一个软惩罚。最终路径、控制轨迹及到位调整须遵守相同硬碰撞规则。`arrival_controller.cpp` 中的终端转动/平移也调用同一查询。
5. **由 Nav2/BT/路由策略管理不可执行、限速及停等。** 不新增底盘末级执行拦截，不改用户固定的idle配置。包络/地图/附着变更撤销上层路径有效性，经现有任务接口结束旧导航并重新规划。
6. **机械臂继续在 MoveIt 三维 PlanningScene 规划。** 底盘路线确定后，停靠姿态与操作目标共用map/scene关联；搬运途中保持已规划姿态。要动臂则在上层任务中先结束该段底盘导航、更新姿态和包络后重规划。本主线不新增边开车边操作双臂的协同优化器。

先不更换规划器、MPPI参数或开启Hybrid执行模式。TEB、GPU预计算和更大规划器对照不属于当前主线必要施工。

## 6. 主线最小场景与决策

| 场景 | 决策及依据 |
|---|---|
| 空载、正常走廊，各有效层净空足够 | 保持现有导航流程；逐层检查通过后执行 |
| 已安全对齐的窄通道 | 若固定航向扫掠通过，直接沿通道通过；通道内不做未验证的原地转向 |
| 低层障碍位于伸臂投影下方，低层包络可避开 | 高度观测完整时允许分层判定通过；不使用整机最宽轮廓误杀低层路径 |
| 底盘可过、躯干/头部/载荷会撞横梁 | 报出具体碰撞层；能在通道外收臂且MoveIt通过则换姿态重规划，否则绕行/不可达 |
| 偏置载荷或非home姿态 | 用真实附着形体和当时关节状态生成各层轮廓，不采用固定对称矩形 |
| 入口/出口需90°转向 | 单独检查转弯扫掠体；空间不足则调整入口/出口路径，不能因直行可过而允许转向 |
| 高度层未知、地面参考不可信、轮廓超出覆盖 | 返回HEIGHT_COVERAGE_UNKNOWN / GROUND_REFERENCE_UNCONFIRMED / ENVELOPE_HEIGHT_UNCOVERED；不能当free放行 |
| 同路径中几何/附着/地图版本改变 | 上层使旧路径失效，重新取得一致快照再规划 |

验收只覆盖上述正常主线及必要的确定性拒绝；暂停恢复、偶发时效问题、完整扩展矩阵后置。

## 7. 尚需补齐后才可在线放行

现有档案没有可靠的逐射线起点与观测体积，因此本轮静态图可提供障碍占据证据，**不能独立证明高层空间空闲**。在线分层规划使用前，必须补充以下一种可核验的自由空间来源：

- 仿真世界完整碰撞几何与明确地图范围生成的真值占据/空闲体积，仅作为仿真规划验收；或
- 带原始时间、准确传感器原点/视场/有效深度的三维ray/voxel观测，按各高度段更新观测覆盖。无回波、遮挡后区域和空消息不能直接清空。

将该覆盖与静态端点图组合后，先完成分层查询及少量固定场景，再接路径和局部控制；不能将当前全部unknown的地图直接替换Nav2自由空间地图。动态更新、闭环修正和地图切换以后按完整快照/地图版本重建提交，不能沿用当前静态产品的加载时间冒充传感器新鲜度。
