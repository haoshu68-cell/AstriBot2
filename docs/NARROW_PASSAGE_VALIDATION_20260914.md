# 窄通道入口修复与宽度边界验证（2026-09-14）

后续整体复审已确认：本报告只证明其指定版本和场景的专项结果，不能作为当前工作区 P5 完整放行依据。原完整目标后续试验仍失败，1.30 m 不是通用最小可通行宽度。当前缺陷、反例及“不可低于历史表现”的验收要求见[窄通道整体复审](NARROW_PASSAGE_REVIEW_20260914.md)。

## 适用范围与结论口径

本轮验证 P5 自动识别的已知地图直通道，实体墙与静态地图一致，机器人使用 0.62 m × 0.62 m 的 simulation_transport 空载运输包络。宽度按 0.05 m 步长验证，结果不是机械极限，也不代表真机或任意接近姿态的保证。

历史数据中，通道内最大横向偏差为 0.059023 m，最大航向误差为 2.079717°。每侧保留净空 0.08 m、边界预算 0.05 m、跟踪预算 0.05 m。用准入航向上限 0.05 rad 计算：

`W_detected >= 2 × [0.31 × (cos(0.05)+sin(0.05)) + 0.059023 + 0.18] = 1.128259 m`。

当前 5 cm 栅格保守占据与识别算法使识别宽度比物理宽度约小 0.125 m，因此历史误差预算对应物理宽度约 1.253 m，向上选择 **1.30 m**。该差值与地图对齐有关，不应硬编码成通用常数。

1.20 m 是居中直行条件下的实测可通过宽度；最终代码的侧向接近试验仍曾在入口安全拒绝，不能称为通用可靠最小宽度。1.30 m 是本轮多场景验收宽度。完整数据见 matrix.json 与 release_results.json。

## 修复内容

- 入口预停距离计入全旋转包络、余量和制动距离，避免先逼近门框再要求转向。
- 入口外允许经过地图与预测障碍完整扫掠证明的低速横移居中及对齐。横移目标固定、位移至多 0.30 m、指令速度至多 0.05 m/s；不在通道内部发起原地旋转或盲退。
- 修复角速度上限为零且角速度需求为零时误把平移速度也压到零的问题。
- 已获准进入的直通道使用短租约航向引导，保留原跟踪器 XY 输出，沿用现有角度增益、速度平滑器与最终防护；许可前的普通曲线接近仍走原控制链。
- 入口恢复不能重复续期；实际包络不满足时停车，准备超过统一 30 s 预算返回 CORRIDOR_BLOCKED。
- 出口外转弯通过完整扫掠证明后不再套用无限平行墙投影；全身越过出口及余量前仍保留通道限制。

租约校验 ROS 时间与单调时钟、完整活动路径、坐标系及模式一致性。视觉接口与融合链、SetRobotEnvelope 和双 costmap 包络确认均保留。未恢复全局定时重规划。

ThreePhaseController 原实现与 MPPI 参数哈希保持历史版本一致；本轮新增通道动作与航向引导确实改变通道专项行为，普通跟踪核心没有重写。哈希一致不等同于所有场景的效果保证。

## 仿真方案与判据

通道长 2 m，沿地图 y∈[-4,-2]，物理两壁与静态地图同步修改。机器人通过导航进入各场景起点，未瞬移。换宽度前检查任务结束、停稳且机器人在通道外。Gazebo、RViz 保留运行。

| 场景 | 验证目的 |
|---|---|
| 原停车姿态附近→出口侧短目标 | 验证原入口居中/对齐恢复；不是原远端完整目标 |
| 临时占道 | 初始路径生成后插入障碍，验证让行、清空确认和恢复 |
| 侧向接近 | 从 (2,1,0) 接近通道，验证入口准备与航向收敛 |
| 对向障碍 | 实体障碍分步向机器人移动，验证停车让行与移除后恢复 |
| 通道内障碍插入 | 机器人进入后插入静态实体障碍，验证内部保护；不等价于连续横穿行人 |
| 包络扩大 | 停稳后将声明包络扩大到 0.96 m × 0.96 m、载荷参数 5 kg，验证拒绝进入与恢复 |
| 反向通行 | 验证双向几何与许可切换 |
| 持续封堵 | 验证有界失败，不无限等待或强行穿越 |
| 1.20/1.15/1.10 m 边界 | 区分居中可通行与保守拒绝 |
| 出口转弯 | 验证出门后正常转弯及全身释放条件 |

成功必须同时满足 Action 成功、最终欧式误差≤0.03 m、角度误差≤1.5°、实际中心穿过物理通道、TRANSIT/EXIT 状态证据、全包络不碰墙。障碍场景还需实测停车与障碍间隙。失败场景需正常返回失败而不是进程或订阅故障。记录横向/航向误差、全程旋转矩形间隙、角速度、速度分位数和加速度，完成时长不评分。

离散采样约 50 Hz，离线全包络距离是采样证据；在线仍执行连续更新的扫掠和碰撞防护。动态障碍服务调用的创建/移动事件存在通信时间误差，不能据此宣称已认证制动响应时间。到点与轨迹数值取仿真里程计，尚未验证真实 SLAM 漂移、视觉噪声或 mark 定位误差。

## 未关闭问题

原远端目标 (3.828349,-9.466385,-0.022986) 已穿过通道，但在通道外约 (1.884,-9.224) 出现 P3 NO_FORWARD_REJOIN / CANDIDATE_COLLISION_OR_UNKNOWN，最终 TEMPORARILY_BLOCKED。reported_pose.json 保留完整失败记录；入口修复成功不能改写为原完整导航任务成功。

此前 P3 冷启动航向和连续第四段曲率变化率待办继续保留。曲折通道、复杂三维机械臂全身动态包络、自动后退与真实载荷均未获本轮放行，P5 完整阶段仍未完成。

## 真机验证接口与顺序

1. 实测运输姿态、机械臂/载荷全身包络，经 SetRobotEnvelope 与两张 costmap 确认；验证姿态变化时旧许可失效。
2. 标定制动距离、延迟、横移最低稳定速度、地面滑移与定位误差，将实测误差填入 hardware.template.json 对应参数，不直接照搬仿真宽度。
3. 接入前/侧/后 SensorHealth 覆盖，视觉数据继续使用 /navigation_policy/vision_observations 与融合适配器；验证遮挡、失联、TF 跳变与恢复。
4. 从宽通道低速空载开始，再双向、侧向入口、停走、载荷与障碍逐级缩窄。记录全身间隙、跟踪误差与到点 3 cm / 1.5°，每级通过后继续。

所有场景脚本与回归用例保存在仓库外的 astribot_validation，本仓库只保留产品实现和验证说明。
