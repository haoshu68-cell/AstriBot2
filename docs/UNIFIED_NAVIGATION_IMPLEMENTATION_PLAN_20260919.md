# 统一多场景导航：详细落地设计与逐步回归计划

日期：2026-09-19。状态：**详细设计完成，运行能力待逐步实施和验证**。

上位方案：[原策略与社会导航整合](UNIFIED_SOCIAL_NAVIGATION_DECISION_CONTROL_DESIGN_20260919.md)。本文件把该方案细化为接口、状态转移、代码改动和验收顺序；机器可读清单为 [18 个工作项与 50 项验证用例](plans/unified_navigation_rollout_20260919.json)。清单不是启动器，里面的 `planned/not_run` 不代表通过。

## 1. 交付边界和不能改变的基线

本轮首先完成详细落地设计、场景追踪关系及静态核对。后续按 I0–I6 推进，每个工作项都要执行多场景回归，不能等整套功能完成后才统一测试。任何运行行为改动只有获得本版本证据后才能进入下一项。

保留现有 ThreePhase / MPPI / Arrival 的运动参数、起步对齐、路径航向跟踪、接近与精调、停稳判定以及原桥接职责。时间不作为跟踪性能评分，横向误差、航向偏差、平顺性与到位精度不得靠放宽阈值取得“通过”。当前真机 SLAM 到位档为 3 cm / 1.5°，仿真真值档为 2 mm / 0.1°；区分定位闭环误差与外部物理精度。

当前已经核对的施工约束：

| 代码事实 | 对施工的具体要求 |
|---|---|
| H2 只允许搭配 P2；fixed_v2 要求 P4/P5 | I0 分开运行现有合法配置，不删除兼容检查强行合并 |
| SocialAdapter 和 RouteCoordinator 各自包含 ResolveRoute 服务实现 | I1 将服务所有权统一；社会模块只提供观测/风险/评分，不创建第二个服务 |
| H2 已在扫描策略之外并行确认人员清空 | 保留当前行为，不能把“抽取统一计时器”误做成重新串行等待 |
| 原 P3 在一个请求周期内按 LOCAL→GLOBAL→VALIDATE 处理 | I2 改为按事件所需类别生成；沿用单周期截止时间和过期拒绝 |
| run_episode 只支持 off/h2，且仅接受 initial_goal/new_goal 规划原因 | I0 准备可版本化验证契约；I2 的风险重规划必须绑定证据，不能只扩大字符串白名单 |
| 当前 HuNav 场景适配仅接受显式 Regular 行为 | 非合作、群组等夹具先做能力扩展与独立真值验证，不能只改 YAML 标签就算支持 |
| 现有路线脚本读取 `[x,y,yaw_radians]` | 配置一律用 m/s/rad；人类报告可显示度，禁止混用 |
| 历史 H2 26 个目标来自固定 overlay | 不将历史结果认作当前合并工作区通过；I0 必须重建基线 |

本轮不因清单规划了新能力就修改真机入口。双臂几何、消息、任务仲裁等共享模块的已有工作保留，施工用独立快照与安装目录，避免把其他工作的未验证变更混进本次证据。

## 2. 代码组织与迁移方法

优先保留现有包和节点，用进程内组合代替新增一批 ROS 节点。按照仓库 `robot-runtime-cpp` 约定，新决策、计时、预测和几何内核采用 C++；现有 Python 节点在迁移期间负责消息转换与接口适配，验证、采集和分析脚本保留 Python。下表中的新模块名称是拟定施工落点，不代表文件已经存在。

| 层 | 现有落点 | 拟修改/新增 | 交付契约 |
|---|---|---|---|
| 输入 | observation_adapters.py、fusion.py、social_adapter.py | 社会适配器输出纯事实，后续接入视觉深度/身份关联 | 源时间、frame、序列、epoch、协方差、覆盖与可用性 |
| 决策输入 | contracts.py、execution_context.py | C++ `decision_contracts.hpp`，冻结一次 tick 的输入 | 同一快照下评估所有候选，不跨回调混用版本 |
| 行为选择 | policy_node.py、behavior.py、social_behavior.py | C++ `decision_engine.hpp/.cpp`，组合旧算法输出与任务约束 | 一个 DecisionResult，只有一个发布入口 |
| 等待管理 | YieldPolicy、SocialPolicy、RouteCoordinator 内计时 | C++ `hold_context.hpp/.cpp`，将旧字段逐步迁移 | 一个 episode、一组清空区间、明确时间域 |
| 路线 | route_coordinator.py、planning_session.py、PlanCandidate | 调整请求类型选择；集中 ResolveRoute 与提交确认 | 一次事务，一个 request ID、截止时间与预算 |
| 跟随 | TaskArbiter、现有 path tracking | C++ `follow_reference.hpp/.cpp` 与持久跟随任务适配 | 身份锁与参考更新，不高频新建 NavigateToPose |
| 队列 | 跟随参考模块 | C++ `queue_model.hpp/.cpp` | 有版本的前驱关系，禁止默认超越 |
| 通道 | corridor/fixed_corridor、envelope 系列 | C++ `passage_behavior.hpp/.cpp` 组合几何证据与对向交通 | 几何准入不等于人员通行权 |
| 绕行/超越 | RouteCoordinator、候选验证 | C++ `maneuver_commitment.hpp/.cpp` | 选边、接回、终止位置和承诺有效期 |
| 评测 | tools/social_navigation、run_waypoint_route.py | 复用记录器，补场景事件/独立断言/阶段汇总 | 同版本多场景可追溯结果 |

迁移分两步：先以旧逻辑为唯一执行输出，让新逻辑只做离线回放或明确的影子计算，比较事实、选择和原因；通过后再由新逻辑发布结果。影子模式没有速度或路线提交权，不能顺便打开新行为。切换后删除同一配置内的重复计时和重复服务，保留冻结旧快照作对照，不长期运行两套状态机。

同一工作项内避免同时改预测模型、候选选择和控制增益。例如 I1 只合并职责及计时，未来停止分支在 I2.1 单独接入，便于把指标变化归因到具体修改。

## 3. 详细接口与生命周期

### 3.1 决策输入/输出

```text
DecisionInput（一次 tick 的不可变快照）
  task: task_id, session_id, mode, final_goal, permissions
  version: task/path/map/localization/envelope/clock epochs
  motion: phase, pose, measured_twist, uncertainty, sample_stamp
  environment: static_geometry, tracks, coverage, observation_health
  route: reference_path, active_path, path_risk, candidate_results
  commitment: passage_id / side / target_identity / predecessor_revision
  time: source_time, physical_time, steady_time, paused, reset

DecisionResult
  motion: CONTINUE | SLOW | HOLD
  behavior: CRUISE | WAIT | DETOUR | FOLLOW | QUEUE | PASSAGE | OVERTAKE
  constraint: max_v, max_w, hold, existing alignment/centering/tracking flags
  plan_intent: NONE | LOCAL | GLOBAL | LOCAL_AND_GLOBAL | VALIDATE
  selected_proposal_id, reason_code, evidence_ids, expires_at
  task_disposition: KEEP | FAIL | COMPLETE（是否完成仍服从任务类型）
```

`MotionConstraint` 是限制已有运动的契约，不能创造运动权。首版沿用现有线/角速度及通道标志；方向性约束需要时再版本化扩展，不能在 reason 字符串中编码。`NavigationPolicyStatus` 用于状态摘要；完整候选成本和拒绝证据写诊断日志，避免高频控制消息膨胀。

固定目标是否成功仍由现有到位检查与任务执行结果决定，决策器不能自行发 COMPLETE 绕过精度判据。移动任务的 COMPLETE 只能由显式结束跟随、队列退出或任务定义的完成事件产生，并经过任务仲裁器确认。

`WorldVersion` 沿用已有 task_id/path_revision/map_epoch/localization_epoch/envelope_epoch/clock_epoch。增加移动目标与前驱关系版本时要明确消息 schema 兼容：旧消费者缺少必需字段时不能默认视为已确认。I1 优先用内部类型传递，不为了设计表一次性改所有 ROS 消息。

### 3.2 唯一服务与提交事务

RouteCoordinator 成为唯一 `/navigation_policy/resolve_route` 服务所有者，包含原 P2/H2 的 KEEP/失败响应。关闭换路能力时，仍可答复当前任务状态，但不能请求或返回未经允许的替代路线。

I0 期间的只读复核确认：现有 P2/H2 与 P3–P5 入口互斥，同一合法配置当前不会同时创建两个 ResolveRoute 服务。“统一所有权”是为后续组合能力消除两套实现，不能写成已经观察到两个服务争抢。I1 将服务接收、上下文快照和响应缓存放在一个入口；候选规划器按能力注入，P2/H2 不因统一入口而创建候选请求或取得换路权限。C++ 决策内核只返回提案，由这个入口负责消息转换及提交；社会观测适配器不保留隐式服务创建副作用。现有取消、版本失效和结果超时的回归证据必须重新取得后，才切换执行输出。

事务流程：`REQUESTED → GENERATED → VALIDATED → READY → COMMIT_SENT → ACKNOWLEDGED`。每步核对 task/session/version/有效期，结果失效进入 `RETIRED`。复用当前服务边界，先在内部补齐事务状态；若现有执行状态无法提供可靠 ACK，再扩展结构化确认消息。

- REQUESTED：只接收具备当前路径风险证据或新目标上下文的请求；计一次请求周期。
- GENERATED：候选生成不授予运动权；LOCAL/GLOBAL/VALIDATE 在同一截止时间内完成。
- VALIDATED：二次检查完整扫掠、时空冲突、曲率、接回与最终 yaw。
- READY：继续检查实际停稳、起点漂移和所有版本；候选不能无限续租。
- COMMIT_SENT：提交一次，并维持安全约束；重复服务调用返回同一提交身份，不能重复消耗预算或新建执行。
- ACKNOWLEDGED：通过任务和路径身份确认执行器实际采用了该路线，才允许按新路恢复。仅收到服务成功不能证明路径已执行。

取消、输入失效、包络变化、重定位、时钟 epoch 变化和任务抢占均使未完成事务失效。定位或地图变化后重新校验可更新证据，但不能直接忽略版本不同。原路已安全且尚未提交候选时优先原路，取消无必要请求。

### 3.3 跟随与队列任务接口

先在任务仲裁边界增加持久任务模式，拟采用 `FollowAgent`、`QueueTask` 独立 action 或等价的现有任务扩展，由 I3 接口审查确定一种，禁止同时开放两个相互绕过的入口。

跟随任务至少指定目标 track ID、感知源 epoch、间距策略、目标丢失预算及取消/结束语义；反馈为身份状态、弧长间距、参考版本、等待原因。队列任务增加区域、方向、前驱关系和加入/离开条件。任务配置不能把视觉身份“默认已确认”。任务仲裁器继续在旧执行器终止后移交所有权。

## 4. 决策状态转移与多场景规则

### 4.1 每周期的固定顺序

1. 获取一致快照；处理取消、输入/定位/包络故障和迫近风险。
2. 从当前实际运动预测原路及停车过程；判断原速、减速、静止分别是否可行。
3. 检查任务语义和通道许可，形成允许的候选集合。
4. 需要替代路线时异步请求适当类别；已有安全约束持续生效，不阻塞控制回调。
5. 筛除硬不可行候选，再按承诺稳定性、跟踪可行性、平顺性、社会舒适性和任务进展排序。
6. 合并所有约束取交集；发布唯一结果；最终防护独立复查实际速度和最新障碍。

没有人员或人员与路线无关时，社会增量为零。任务进展只用于避免没有理由的无限等待，不使用总耗时或追求高速度的奖励覆盖质量目标。

| 状态 | 进入条件 | 输出与持续检查 | 退出/失败 |
|---|---|---|---|
| CRUISE | 原路按基线可执行 | 原限制，持续检查 | 风险出现转 SLOW/WAIT 或提出候选 |
| SLOW | 可实现的减速轨迹安全 | 按原平滑链限速，保留已执行速度的停车空间 | 清空后恢复；近风险可立即 WAIT |
| WAIT | 当前不能安全前进，但保留任务 | 零速约束；检查停驻点未来占据与输入 | 全部条件满足转 CLEAR_CONFIRM；到期按原因失败 |
| CLEAR_CONFIRM | 所需条件均已开始持续成立 | 共同有效区间与停稳并行 | 新风险返回 WAIT；共同区间够长且有合法运动意图转 RESUME |
| RESUME | 清空、实际运动状态、任务/路径均有效 | 从当前状态沿既有平滑链恢复 | 新风险立即覆盖；否则 CRUISE/SLOW |
| ASSESS_ROUTE | 当前风险支持生成替代路线 | 安全等待或已经证明安全的原路动作 | 候选合法且可接管后提交；无解/超时有界失败 |
| COMMITTED_MANEUVER | 合法侧绕/超越/通道动作已获确认 | 维持选边、路径和版本；每周期再评估 | 完成、取消或硬风险撤销；不能因软代价抖动换边 |

HOLD 不总是安全状态：人员可继续进入静止机器人位置。存在已验证机动时才选择退出；否则保持停车并报告 NO_SAFE_MANEUVER，保留实际碰撞统计，不能以“命令为零”宣称避免了碰撞。

### 4.2 计时的精确定义

| 计时项 | 起点/累计方式 | 重置或结束 | 时间域 |
|---|---|---|---|
| 观测有效期 | 采集源时间及对应序列 | 新有效源帧更新；重复帧不续期 | 源时钟，hardware 同时校核接收时效 |
| 清空确认 | 各必要条件连续成立区间的交集 | 任一条件失效重置该条件区间 | 物理时间 |
| 停稳窗口 | 去重且质量有效的实际运动反馈 | 明确运动或无效反馈按既有停稳契约处理 | 物理时间 |
| 普通阻塞 episode | 首次阻塞 HOLD | 持续清空并恢复有效进展后结束；换 ID/路径不重置 | 物理时间 |
| 请求周期 | 单次 PlanningSession.request | 响应完成/过期/取消；子请求不续期 | 单调时钟 |
| 每目标请求次数 | 每个授权请求周期计一次，最多 5 次起点 | 只有真正新任务目标才重新计数 | 计数，无时间重置 |
| 跟随/队列正常等待 | 显式任务语义事件 | 人恢复运动/任务取消/任务预算到期 | 物理时间 |
| 控制租约/服务失联 | 依现有传输契约 | 新合法指令/服务恢复；旧命令不可复活 | 单调时钟或既有 ControlTime 契约 |

统一清空起点可写为 `max(clear_since_i)`，前提是所有必需条件当前仍为真且区间连续；不是取最早一个条件。普通 episode 的 30 s 包含等待、规划与校验，8 s 不再是所有动态障碍升级的硬等待步骤。HOLD 只暂停控制器运动无进展时间，不暂停任务故障或输入检查。

仿真暂停使物理计时停止，但服务请求仍可按单调时钟过期。暂停期间不发新规划申请，不消费新的重试次数；已计次数不退款。恢复后根据新输入和上下文重新判定，不能提交暂停前过期结果。时间回跳重新建立 epoch，明确记录旧任务终止或重新建立上下文的原因。

恢复额外延迟的设计目标为不超过 3 个已冻结控制周期：从“所有释放条件满足且控制器有合法非零运动意图”到解除策略 HOLD。该指标不包含规定的 0.6 s 清空窗口，也不把物理加速滞后算作计时重复。实际周期及采样分辨率必须记录；I0 未具备测量能力前不能判此项通过。

### 4.3 让行、绕行、重规划的决策表

| 当前证据 | 可选行为 | 规划请求规则 | 不允许的行为 |
|---|---|---|---|
| 短暂横穿且原地等待安全 | 原速/减速/等待 | 通常 NONE | 每次有人经过都全局重算 |
| 远处冲突，减速可错开 | SLOW | NONE | 无必要完全停下 |
| 持续动态占用，已知侧通道可用 | WAIT/LOCAL | 当前风险和持续性证据满足才请求 | 每 8 s 无条件重试 |
| 局部静态障碍 | LOCAL/WAIT/GLOBAL | 依局部通道证据选择 | 只绕过障碍前半段 |
| 整条通道阻断且有另一连通路径 | GLOBAL/WAIT | 可直接 GLOBAL，不强制先 LOCAL | 用 timer 而无风险证据触发 |
| 原路恢复安全 | 原路恢复 | 退休未提交候选 | 为使用已算出的新路强行换路 |
| 目标位置占用 | WAIT/GOAL_OCCUPIED | 终端区不以替代终点绕行 | 改目标、改 yaw、放宽精度 |
| 无新输入/服务不可用 | 安全等待或有界失败 | 不把不可用信息当作规划证明 | 空消息即全速放行 |

## 5. 新行为的施工细节

### 5.1 跟随和队列

跟随沿目标历史轨迹按弧长回退生成参考，间距至少覆盖完整几何、制动空间及舒适间距；不能减去假设的前人滑行量。历史不足时先生成合法连接，不直线切角。小幅参考推进保留 FOLLOW；身份/拓扑/大方向改变时重新接管，暂停不进入固定目标到位完成。

状态：ACQUIRE/FOLLOW/TARGET_STOPPED/OCCLUDED/REACQUIRE/FAILED。ID 重用或源 epoch 改变不自动视为同一人；重捕获先证实身份再验证连接路径。队列在此基础上增加 JOIN/QUEUED/ADVANCE/LEAVE 和前驱版本。插入或离队期间先稳定关系再恢复，不依据最近距离跳过人。

### 5.2 超越和退让

PREPARE 必须验证驶出、并行、接回、对向净空和全过程停车位置；差速不足保持跟行。PASS 后锁定侧向承诺，REJOIN 要包含机器人尾部以及被超越者净空。新硬冲突可以撤销承诺，但“回原路”同样需要一条有效候选，不能直接倒退。

后方退让需要覆盖有效、完整包络路线和可停终点。原起始退出执行部件可复用，其历史通过不等于对人退让通过。队列、跟随任务以及窄通道默认无超越权限，权限由任务上下文约束而非各模块自设布尔开关。

### 5.3 窄通道和双臂包络

先在独立原 P4/P5 配置复验几何，再组合人员策略。机器人机身、双臂、载荷和高度切片使用同一包络版本；预留轮廓与已经膨胀安装轮廓不能重复加安全量。

准入 = 当前包络扫掠可行 ∧ 每侧净空预算足够 ∧ 航向/横向误差可控 ∧ 相关感知覆盖有效 ∧ 出口/停车可行。0.85 m 内禁止原地转向。已对齐且准入成立可直入；入口修正不能形成无穷居中往复。许可在完整机身离开出口后解除，epoch/租约改变即重评。

仿真附件过滤确认分为两项证据：实际成功过滤的点云采集时间决定数据有效期；配置确认心跳说明该版本过滤器仍存活。心跳不能刷新点云时间或替代新观测。仅当版本一致、快照和最后成功点云均未过期且时钟持续前进时可继续确认；无效帧、版本切换、时钟回退或暂停后需要新成功帧恢复。接收端原 0.5 s 墙钟失联保护保留。I0 的独立候选正在复测该契约，不能据离线通过宣称通道通过，也不向真机开启附件过滤。

### 5.4 历史停车数据与执行补偿

复用既有 16 次四方向 SLAM 峰值参考和 stop_reference 转换，不重复叠加尾程或安全余量。实际速度覆盖约 0.053–0.249 m/s；0.35 m/s 指令不代表实际速度达到 0.35 m/s。超范围是仿真解析延伸，必须标识。

新增未来停止分支和有界加速度/转向不确定度，覆盖当前实际速度的完整停车时域。正常平滑停、迫近零速、旋转与复合运动分别建立校验，直线历史参数不能认证全部运动。原低速打滑补偿继续在控制层，HOLD/占用/输入失效时不能因无位移提速，恢复不能重放累积修正量。

I0 的 R03 夹具 v2 将历史先验的比较起点明确为下游最终零指令，另外完整记录平滑器前原始置零到停稳的位移；后者仍须通过 I2 的正常停车预测验收。原因是历史先验的模式为 `preview_0.5s_zero_edge_actual_position_hold`，原文件已经明确不覆盖正常平滑停。v1 后退 0.35 m/s 试验测得原始置零后 0.521 m 行程，不能套用当时实测速度的 0.254 m 尾程预算；该失败保留，不用平移计时起点宣称完整正常停车已通过。最终防护的带时间戳 HOLD 还须独立测尾程、命令持续为零、停稳和几何，不能与正常降速试验互相替代。

I0 四方向首轮进一步确认：0.35 m/s 脉冲原始置零时实际速度仅约 0.125–0.132 m/s，完整平滑停峰值余移却约 0.521–0.524 m。原有 Ruckig 平滑器保留其当前输出速度和加速度，收到零目标后仍需按 jerk 约束完成速度轨迹，随后才是执行器尾程。I2 的正常停车预测必须冻结实际速度、下游指令、平滑器当前加速度、时间戳及限制版本；只把当前测量速度代入历史二次式不构成足够证据。应预测现有平滑器的零目标轨迹，再计入执行响应不确定度及完整机身扫掠，避免重复叠加已有余量。预测器不能发布速度或修改原平滑参数。

I2.1 专项回归需区分“仍在加速时置零、稳定运动时置零、已经减速时再次置零”，并组合四方向、延迟/旧帧和约束突然收紧。1.6 s 脉冲没有保证进入稳态，不能将其作为稳态速度或稳态制动认证。缺少平滑器状态时应明确降级为保守停止边界，不将未观测的加速度默认为零。此补充是后续设计约束，尚未实现或验收。

## 7. 可执行场景的构建方法

### 7.1 50 项目录及覆盖关系

- H2-00～H2-07：8 项既有夹具，保留原文件和历史通过边界，当前版本待重跑。
- S01～S28：与整合方案 28 类场景逐一对应，补齐身份、接管、通道和探索等新行为及边界变体。
- R01～R14：跨场景的取消、计时、曲率、异步竞争、感知融合、停车、实时性与驻留专项。

清单给出每项的触发、预期、禁止行为、重复次数、首次实施阶段、所用独立判据和夹具准备状态。既有 H2 部分覆盖某个 S 场景，不等于已覆盖该场景的所有新行为；测试结果不能按标题相似就互相借用。

### 7.2 坐标、目标与事件

所有场景定义一个已验证自由区域中的局部坐标系，先与本轮地图对齐并检查全路径几何，再发送目标。基准无人路线沿用 `[2,0,0] → [0,0,0]`；90° 终点变体采用 `[2,0,π/2] → [0,0,0]`。L/U、通道和侧绕采用专门夹具，不把这些坐标直接放进带柱子的原世界。

行人初始位置、圆柱代理、人形显示、实际接触/传感器几何必须对应。未来横穿/停止事件以机器人路径弧长、距离冲突区或明确控制阶段触发，物理时间只用于有意的持续时长。超时兜底触发要标记；没有形成预期冲突只能 INVALID_FIXTURE，不能算算法通过。

停走、折返、迎面不合作和队列插入需要场景执行器支持独立人员事件。目前全局 start/pause 不足以表达所有情况，应扩展显式的 agent ID + event sequence + ACK 接口，限定在仿真包，并验证事件施加到了正确人。不得把人的隐含目标/行为标签输送给机器人决策器；它们只进入独立评测。

### 7.3 参数化覆盖与重复

| 维度 | 最低覆盖 |
|---|---|
| 路线 | 正向/返回、90° 目标朝向、直线与曲率变化 |
| 人员 | 左/右、同向/对向、单人/双人、合作/不合作；后期群组 |
| 冲突时机 | FOLLOW、接近、REFINE、WAIT、候选 READY、PASS/REJOIN |
| 观测 | 正常、0.3 s 边界两侧、丢失、重复、future stamp、遮挡/ID 变化 |
| 几何 | 正常/边界/不满足净空、0.85/1.0/1.2/1.8 m、包络变更 |
| 停车 | 四方向、历史速度范围内/外、实际速度与指令不一致、旋转另列 |
| 异步 | 取消与响应不同顺序、版本改变、请求超时、原路恢复 |

不盲目做全部维度笛卡尔积。先逐项边界覆盖，再做相互作用的成对组合；停止距离×观测延迟、通道宽度×包络×航向偏差、取消×COMMIT 是强制联合维度。每个声明变体至少 3 次有效闭环，无人至少 3 对交替 A/B，窄通道质量至少 5 对；基线和候选顺序交替。场景种子固定并记录，MPPI 不支持固定种子的部分明确报告波动。

## 8. 判据、工具扩展和结果格式

### 8.1 独立判据

JSON 定义 O01–O16 判据，覆盖所有权、几何、输入时间、任务精度、质量、规划预算、释放计时、曲率、身份承诺、实时性、夹具有效性、双视图地图、停车、命令响应、补偿约束、探索活性。

独立几何必须来自实际仿真机身/人员姿态及完整包络，不能用策略自己的 risk=false 当无碰撞证明。相邻采样间需连续扫掠或可证明的保守插值误差；缺少此证据应报告采样覆盖限制。采用离线已知相交/不相交几何检验 oracle，不修改运行防护来制造测试通过。

共同硬条件：无过期候选提交、无越权输出、普通可行场景零重叠且满足净空、固定目标不改变、该到位档及停稳通过。非合作主动冲撞在独立类别验证及时动作和 NO_SAFE_MANEUVER，保留重叠事实，不能混入普通零碰撞统计。

质量按每目标和相位比较：横向 P95 容差 `max(0.005 m,10%)`，航向 P95 `max(1°,10%)`，实际 jerk P95 `max(0.1 m/s³,15%)`，作为随机波动识别范围，不用于主动调差。主动绕行相对原路径的偏离另列，跟踪误差只对当前有效执行路径计算；身份跟随距离与固定目标到位误差分开。

速度响应使用同一源时间的指令/实际运动；报告估计延迟、对齐后的稳态增益及残差，保留原始时间轴。相同时间戳不能参与速度/jerk 差分，缺数据不能填零获得优秀指标。总耗时仅记录，不参与性能排序；场景完成期限用于防止无限运行，失败时按死锁/阻塞/执行问题定位。

### 8.3 结果与晋级

每次运行记录 case/config/source/runtime 哈希及父工作项，结果使用 `PASS / FAIL / INVALID_FIXTURE / INFRA_FAILURE / BLOCKED / NOT_RUN`。只有明确未启用可选能力的专属项允许 N/A；必需项缺失不可跳过。算法失败须修复后重跑公共集和受影响专项，阶段结束累计回归；基础设施重跑也保留前一次日志与原因。

每个可执行变体必须写明 `expected_task_outcome`、`expected_reason`、必须出现/禁止出现的事件及其时序。取消用例预期任务 CANCELED，长期目标占用预期 FAILED/GOAL_OCCUPIED；“正确地拒绝或退出”可以是该用例 PASS，但不能算到位成功。原 H2 记录器的 `all_goals_passed` 只适用于其成功到位夹具，新验证器不能用同一布尔量裁决全部异常用例。非合作不可避接触还要单列 `contact_unavoidable_fixture` 与实际重叠量，不能隐藏在 PASS 后面。
