- 延续 C++ 短接收回调、有界精确配对、单待处理槽、独立 CPU/CUDA 工作线程和发布前双时钟检查。原 250 ms 门槛保持不变。

- 启动监督器新增 `--exclusive-performance`。普通会话持共享文件锁，独占验证持排他锁；锁 inode 不删除。启动前识别现存 Gazebo，包括 Ruby 包装、绝对路径命令和改写后的进程标题，避免把工具 shell 中的文本当进程。没有自动杀进程的行为。

## 恢复契约修复

`camera_health_node.cpp` 增加连续性 generation：健康失效只切换一次版本，重复故障保持稳定；clock rollback 或 session token/active/owner/execution/activated_at 上下文改变使用新版本。epoch 从固定 base 重建，不逐次串接增长。

保留旧匹配帧的 capture/expiry 供诊断，但恢复必须满足两个条件：新完整帧组的匹配序号通过屏障，且最早采集时间严格晚于故障/重新授权时的采集水位。普通同会话心跳不推进水位。畸形输入、frame/尺寸矛盾和内参漂移在接收回调锁存断点，覆盖两次健康发布之间的短故障。会话无效期间接收的帧、恢复后才送达的旧采集帧都不能重新授权。

证据：旧实现初始 5 个缺陷用例全部失败；延迟旧采集帧另有独立 RED。当前相机健康 27 个 C++ ROS 用例通过；CUDA 候选完整 14 个 CTest 目标通过（其中 12 组 GTest 共 118 个用例、2 个既有原生测试目标）。新增真实 CameraHealth→DetectionGate 链验证旧候选在 40 ms ROS 年龄时明确触发 `CAMERA_SOURCE_MISMATCH`，新版本/新采集时间正常输出；不是通过超时构造拒绝。增强后的该测试单独复验通过。

运行安装为独立 `health_epoch_cuda_overlay`，原 30 分钟压力数据仍对应 `metrics_overlay`，不能把旧压力结果移签给新版本。导航04曾以未开启 CUDA 的构建启动，发现组合不符后已停止，自有残留为零；导航05改用明确启用 CUDA 的候选。头腹 CPU、双腕 CUDA 不变。原始 CameraHealth 仍只反映输入流，不能证明投影 worker 本身健康；GPU 硬挂起与处理状态门控另行验收。

camera_05 完整窗口为 600.001160 s，RTF 0.997846；实际暂停 400.718 ms，观察者时钟接收最大间隔 402.458 ms（一次 >250 ms，无回退）。四路故障期间 epoch 不抖动，恢复后直到窗口结束只出现一个健康 epoch。头/腹/左腕/右腕首个健康恢复观测距 resume 为 109.58/60.38/77.47/73.67 ms；这是观察者接收时刻，不是传感器物理响应时延。

仅一次暂停真正执行。首次前置检查未通过，第二次诊断重试执行；另一次重复注入尝试因 odom 消息先于 clock 造成连续停稳检查未满足而未发送暂停信号。两个未注入记录都是无效实验，不算恢复通过或机器人故障。原时效/停稳判据没有放宽。重复故障仍需修正验证侧消息对齐后另测。

对应 `clock_pause_05_analysis.json`、`camera_05_window_analysis.json`、`health_epoch_runtime_05.json`。腕部任务准入/释放/期限用例通过并清理；导航05经新鲜里程计确认六维速度为零后请求自有监督器退出，自有剩余进程为空。该结果不包含真机停止、运动制动、GPU硬挂起或完整W1验收。

## 时延字段与限制

| 字段 | 计时边界 | 样本集合 |
|---|---|---|
| pair_wait | 最早配对输入在回调内登记接收 → 精确配对成立 | 所有被调度的有效配对，含后来被替换者 |
| dispatch_wait | 配对成立 → 工作线程取出且检查通过 | 实际开始处理的任务 |
| compute | 进入 compute → 返回，含布局校验、点云分配及 CPU/CUDA 投影；CUDA 含同步与数据拷贝 | 计算完成者，含随后过期/失效者 |
| publish | 调用 DDS publish → 返回 | 发布成功者 |
| receive_to_publish | 最早配对输入登记接收 → 发布返回 | 发布成功者 |

这些是**节点生命周期累计**的直方图上界分位数，不是精确滑动窗口分位数；不同阶段样本集合不同，分位数不能相加。超过 409.6 ms 的分位落点以生命周期最大值作保守上界。接收登记发生在回调取得互斥锁之后，不包含 DDS/executor 排队；计算结束后再次取锁的等待只计入总时延，未独立分段。发布与失效提交仍共享短锁；不作硬实时承诺。

观察者的 capture-to-receive ROS age、wall receive interval，与节点内部处理时延分别报告。当前统计仍缺独立传感器采集、桥接、TF、推理动作端到端关联探针；GPU 驱动硬挂起的进程级恢复也未验收。不得把 CPU/CUDA 微基准或局部分段低延迟当作整个链路已解决。

时钟接收间隔只统计相邻已收到的消息；新增 `tail_silence_wall_sec` 单独记录窗口结束时距最后消息的墙钟时长，防止末尾停止且未恢复被零长间隔次数掩盖。无样本时该值为空；零样本不是通过。

## 相机连续性修复（C++，当前候选）
