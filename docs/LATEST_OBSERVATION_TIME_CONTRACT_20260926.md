# 当前主线统一时间语义

用户于2026-09-26授权替代原来分散的观测时效阻断规则。本文件为本次施工契约；实现、构建与实际加载分别记录，不因文件存在宣称完成。

- `sample_stamp/header.stamp`：来源采样时刻，用于同来源、同session的最新样本选择及配对。倒序消息忽略，重复消息不冒充新的源进展。领先本节点ROS时钟的新样本也接收，不因此错误或停止任务。
- 配对时间：同相机、frame及标定上下文中选择最近可用样本；TF优先已有所需时刻，无法覆盖时使用最近可用/latest变换。保留原采样时间与实际匹配时间，不把旧样本重盖章伪装新采样。
- `receive_steady`：本地处理顺序、处理延迟及持续动作/停稳窗口的时基。ROS时钟到达先后不改变该时基。
- 连续观测及正向派生快照的`valid_until`和年龄：不再作为主线STALE/EXPIRED/INVALID、清空状态或撤销许可的依据。结构字段可继续携带，不能靠每层重新盖时间证明源已更新。
- 来源、session、对象/附件/几何修订及明确负确认：继续表示数据身份和业务状态。新时间戳不把负确认变成允许，不把缺失对象、错误坐标或非法数值变成有效事实。
- 资源租约、Action/服务等待、取消、无进展和连续停稳：用steady时长，不由传感器时间领先或ROS回退触发超时。轨迹自身的执行时序及物理速度计算不改为任意接收时间。
- 启动缺数据先等候已有阶段预算；有数据的接收回调只更新缓存。不会因源时间相对本节点早/晚立即终止整个任务。

本次必要范围：当前导航仿真中的传感器健康/点云、关节/载荷/几何、包络及ACK、起点恢复和普通导航的观测消费、MTC/搬运执行器、实际使用的验证脚本。VLA、真机、未启用算法及新场景不在本轮范围。

验收顺序：源领先与延迟正向消息不阻断；倒序不覆盖、最近配对有效、明确负确认有效；核心依赖构建与夹具；统一实际产物后，同一正对操作台场景完整PICK→必要起点脱困→NAVIGATE→PLACE并录屏。`idle_position_hold=true`、`idle_position_kp=3.0`及几何/碰撞/到位精度配置保持既定值。
