# 离线复盘操作与多场景验证手册

版本：2026-09-23，面向当前 `astribot_operator_station` 工作树。配套 [评审报告](../OFFLINE_REPLAY_UI_REVIEW_20260923.md)。

**先明确当前能力：可以查看事件及历史参数、回放地图/路径/里程计/TF；还不能保证点击事件后画面与参数自动对齐。** 本手册将“现在怎么用”和“修复后怎样算通过”分开写。已有缺陷不能记作操作人员失误。

## 一、选择正确入口与资料

| 入口 / 资料 | 用途 | 边界 |
|---|---|---|
| 统一工作站 → 日志与回放 | 开始/停止记录、人工故障标记、关键参数快照、打开独立回放 | 采集按钮需要在线后端、已启动记录器及当前控制权；离线打开不需要申请控制权 |
| 打开只读 3D / 参数回放（独立进程） | 一个回放控制窗口 + 一个独立 RViz 窗口 | 不是在在线工作站里重新执行任务；关闭在线工作站可能影响其控制租约，不要把它当关闭回放 |
| 旧 OperatorPanel → 打开离线事件 / 参数回放 | 仅按事件接收顺序查参数，含上一事件、下一事件 | 每 0.5 秒一条，不是原始速度；不是 3D 回放，事件上限 10000 |
| `incident_<数值时间戳>_<PID>/` | 本模块的诊断包 | 与统一启动日志的 `sim_<时间>_<PID>/` 不是同一种目录，不要互相代替 |

完整诊断包的典型内容：

```text
incident_.../
├── manifest.json       # 结束状态、机器人/部署版本、质量、故障
├── events.jsonl        # 严格递增 sequence，事件及参数证据
├── session.log         # 记录器自身日志，不代表所有 ROS 节点日志
└── bag/
    ├── metadata.yaml
    └── *.db3           # 可有多个分片，必须一起保存
```

默认记录目录是 `/tmp/astribot_incidents`；假后端启动配置为 `/tmp/astribot_fake_incidents`。实际以记录器返回的 `directory` 为准，启动参数可能覆盖默认值。`/tmp` 不适合长期留存，停止落盘后将**整个诊断包**复制到项目指定归档目录。不要只复制一个 db3 文件。

本轮没有验证既有安装目录与当前源码是否完全一致。正式验收应记录安装前缀、源码版本和构建记录；本轮探针从当前源码另行构建，没有覆盖安装目录。

## 二、在线采集一份可复盘资料

已有诊断包可直接跳到第三节。本节在自己拥有的仿真会话中操作；本轮评审没有替你启动或执行这些动作。

1. 打开已有统一工作站的“日志与回放”页，确认后端在线、记录能力可用。采集记录器应在机器人/仿真侧，只部署一个相应记录器。
2. 使用该会话当前操作员的控制权。若无人持有，按正常流程点“申请控制权”；若提示忙，不抢占他人的会话。
3. 点“开始记录”。它调用已经运行的记录器服务，**不会凭空启动记录节点**。确认返回成功、目录非空、消息数开始增加。按“开始”前发生的事情没有预触发缓存，不能补录。
4. 点“关键参数快照”。请求被受理不等于快照完整；等事件中出现 `parameter_snapshot`，或记录 `parameter_gap`/unknown。各节点顺序读取，并非所有节点的原子瞬间快照。
5. 在原有仿真流程中执行本次要观察的一个场景。出现异常时点“人工故障标记”，另行记录现象、任务/命令 ID、截图和对应操作时间。当前标记没有自定义文字输入。
6. 场景结束点“停止记录并落盘”。确认停止成功，然后检查 `manifest.json` 的 `state` 为 `closed`；有 `partial`/`fault` 时保留原包，并将本次记为不完整记录。
7. 检查清单中的 `topic_quality`、`parameter_quality` 与缺失主题。缺 TF、地图或参数时，不把“文件已经生成”记为采集完整。机器人/部署版本为 `unknown` 时，另行补充测试记录中的版本信息，不伪造原始清单。

若能力不可用，先核对记录器是否启动和 ROS 会话是否一致。包提供的 `operator.launch.xml` 默认 `recorder:=false`；在已有后端、尚无记录器且需要该启动入口的环境中，可使用：

```bash
source /opt/ros/humble/setup.bash
source /home/yjh/WorkSpace/astribot_sdk_ros2/ws_robot/install/setup.bash
ros2 launch astribot_operator_station operator.launch.xml recorder:=true use_sim_time:=true
```

这会启动记录器和 RViz，**不会启动 Gazebo、导航或 operator_backend**。沿用当前仿真会话的环境；不要在已经运行记录器时重复启动。真机不适用这里的 `use_sim_time:=true` 示例。

可选只读核对（在采集侧相同 ROS 环境下）：

```bash
ros2 param get /diagnostics_recorder output_root
ros2 param get /diagnostics_recorder use_sim_time
ros2 topic echo /diagnostics_recorder/status --once
```

## 三、打开与基本查看

1. 在“日志与回放”点“打开只读 3D / 参数回放（独立进程）”。选择包含 `bag/` 和 `events.jsonl` 的 **incident 根目录**，不要选 `bag/` 自身或 `sim_.../`。
2. 确认控制窗口标题是 `OFFLINE · 只读 3D 与关键参数回放`，并出现另一个回放 RViz。在线工作站与回放窗口分开摆放，避免把当前机器人画面当成历史画面。
3. 地图参考系默认从记录地图的 `header.frame_id` 提取，没有找到则默认 `map` 并提示。TF 报错时先检查记录内容和真实参考系，不随意改成另一个名字来隐藏错误。
4. 打开后会自动播放，不是默认暂停。点击“暂停”后观察顶部当前时间是否停止变化；当前没有单独的暂停确认灯。稀疏消息本来就可能时间不变，不能只凭短时间不变推断暂停成功。
5. 输入框 `1.00 x` 是倍率，范围 0.1～4；带 `s` 的框是**跳转目标**，不是自动跟随的播放进度。当前时间在顶部文字中。
6. 默认 3D 显示地图、路径、里程计、TF。没有点云/相机、完整机械臂动画或所有业务状态的默认显示，不代表它们正在正常回放。
7. 播放结束会保留末帧。当前点“播放”不会从头再来；将目标设为 0，再点“跳转并重建”。
8. 退出时关闭 OFFLINE 控制窗口，由它回收自己的播放器和 RViz；不要使用全局结束 ROS/Gazebo 的方式清理回放。

如果点开后没有窗口，可从终端打开同一包查看错误：

```bash
source /opt/ros/humble/setup.bash
source /home/yjh/WorkSpace/astribot_sdk_ros2/ws_robot/install/setup.bash
# 将下面路径换成已有、停止落盘后的 incident 根目录
ros2 run astribot_operator_station replay_viewer /实际归档目录/incident_...
```

当前界面不会完整显示清单质量，打开前需自行核对。`recording` 状态不作为正式复盘样本；`partial` 仅按不完整证据分析。坏 JSON、序号重复、bag 缺失或数据库打不开时先保留原包，不直接修改原始证据。

## 四、定位事件与查询关键参数

### 当前版本的可用步骤

1. 点“暂停”，确认播放游标停止。
2. 选中列表事件，查看 `sequence`、`kind`、`ros_ns`、节点及参数值。**选中只查看详情，同时填入定位目标；不会立即让 RViz 跳到该事件。**
3. 需要查看该时刻附近画面时，再点“跳转并重建”。两个子进程会重建，原来手工添加的 RViz 显示项会丢失；随后自动播放。
4. 当前重建存在加速追赶和旧详情残留缺陷，不能靠“立即点暂停”保证停在准确帧。严格故障归因时，以事件序号查询参数，并把画面仅记为附近上下文；不能声称二者精确同步。
5. 回到首次参数事件之前，若仍显示先前值，应记为 F3 复现，不能把它认作当时已经生效的参数。

按事件序号单独查询，不依赖 3D 游标：

```bash
# 123 为要检查的真实事件 sequence；省略则查看最后状态
ros2 run astribot_operator_station inspect_incident /实际归档目录/incident_.../events.jsonl 123
```

也可在 RViz 的 `Panels → Add New Panel` 中添加 `astribot_operator_station/OperatorPanel`，仅使用“打开离线事件 / 参数回放”；无需通过旧面板发送导航或其他控制命令。

| 字段 / 值 | 正确解释 |
|---|---|
| `observed` | 某次读回获得参数，不能证明控制器执行周期已经应用 |
| `event_only` | 有参数变更通知，可能只覆盖部分参数 |
| `unknown` / `parameter_gap` | 数据或身份链不连续，不能用前一值或默认值补齐 |
| `available: false` | 参数被删除或不可用，不等于 0 |
| `node_instance_id` 变化 | 节点端点身份发生变化，需要重新建立参数上下文；不是固件启动 UUID |
| `effective_confirmed: false` | 当前实现没有设备生效确认 |

参数清单是显式白名单，见 `config/recorder.yaml`。没有列入的参数不能事后恢复；旧包也不能靠升级查看器补出从未记录的数据。仿真重启、时间回退或长期冻结时，优先按序号查看，并将跨时钟段的 3D 对齐标为不可信。

## 五、虚拟墙、禁区与 SLAM 关联检查

当前 `/operator/zone_markers` 可录制且允许前缀回放，但默认 RViz 配置没有添加显示项。

临时查看方法：在**回放 RViz** 的 Displays 中添加 `MarkerArray`，Topic 选择 `/astribot_replay_<本窗口标识>/operator/zone_markers`，Durability 选 `Transient Local`。本窗口标识可以从 Map 的 Topic 前缀核对。不要选在线原始话题来“补齐”历史画面。该步骤本轮未做真实 RViz 渲染验证。

注意：

- 每次跳转重建都会更换前缀、重建 RViz，需重新添加。
- 没有标记数据时应显示不可用；不把在线区域文件冒充历史区域版本。
- 看见虚拟墙图形只能证明标记被显示。是否对导航/探索生效，需要同一地图/会话版本的约束、消费者 ACK 和任务结果。当前界面未将这些整合为完整证据链。
- `/navigation_zones/events` 虽可进入 bag，当前不会自动成为事件列表中的 `operation_event`。探索完成、取消、保存/载图等也必须分别核对实际记录的事件和状态，不能因地图显示出来就判保存或重定位成功。

## 六、多场景验收表

状态约定：READY 是具备本次执行条件，BLOCKED 是缺少条件；PASS/FAIL 表示实际对照判据后的结果，NOT_RUN 表示未执行。已知缺陷仍然是 FAIL，不能因为“符合当前代码”改判 PASS。

| 场景 | 前提与操作 | 正确验收判据 | 本轮证据 / 后续状态 |
|---|---|---|---|
| SC01 正常包打开 | 停止落盘、单一时钟段、含地图和 TF；打开并播放 | 来源/质量可核对，3D 地图轨迹与记录相符 | Qt 窗口 READY/PASS；真实 RViz 画面 NOT_RUN，不能合并判全部通过 |
| SC02 播放/暂停/倍率 | 具有连续及稀疏区间的数据，依次暂停、播放、0.5x/1x/2x | 状态明确；暂停后无后续历史推进；倍率符合时间差 | NOT_RUN；当前暂停状态和输入标签不足见 F6 |
| SC03 事件选中 | 游标在 6 s，选择 1 s 事件 | 明确区分当前游标/选中事件，不能无提示混用 | READY/FAIL：实际 Qt 显示 6 s 与 1 s 参数，E5；真实 RViz 联动未测 |
| SC04 跳转计时 | 1200 条历史样本；跳到 2.4 s，后两帧相隔 200 ms，1x | 隔离轻载探针订阅间隔 200±40 ms；负载不达条件应记环境问题另测 | READY/FAIL：从头 199.138 ms，跳转 1.132 ms；单次证据 E3 |
| SC05 反向定位 | 先选已知参数事件，再跳到第一个事件之前 | 清空旧详情；参数标 unknown/尚无证据 | READY/FAIL：当前 0 s 仍留 1 s 的 0.3 值，E5 |
| SC06 EOF 与重复定位 | 播放到结束，再播放、从头定位、暂停后定位 | EOF 操作含义明确；定位恢复状态可预测 | NOT_RUN；源码确认播放按钮在 EOF 不重新开始，见 F6 |
| SC07 坏包/中断包 | 仅对复制的样本删除 bag、破坏 JSON、使用 partial 清单、使子进程退出 | 明确错误和证据不完整；无错误窗口静默消失或旧画面冒充成功 | JSON/序号底层拒绝逻辑 READY/PASS；完整 GUI 错误交互 NOT_RUN，见 F5 |
| SC08 时钟回退 | 仅用合成数据，按 20、21、1、2 s 写入 | 保留时钟分段，或明确拒绝跨段关联 | Reader 实验 READY/FAIL：顺序变成 1、2、20、21，未保留段身份；完整跨段 GUI NOT_RUN |
| SC09 控制命令隔离 | 隔离 bag 含地图与历史 cmd_vel；运行播放器并观察发布者 | 有前缀地图，无原始/前缀 cmd_vel 发布，无任务执行请求 | cmd_vel 契约 READY/PASS，E2；不能外推所有消息类型和真机安全验收 |
| SC10 禁区/地图业务 | 同一 session 有绘墙、提交、ACK、存图/载图记录 | 图形、版本、事件、应用状态对应；未录数据明确不可用 | 默认显示缺项源码已确认；手动 MarkerArray 与完整业务链 NOT_RUN |
| SC11 参数缺口/重启 | 使用合成事件覆盖删除、端点变化、快照缺口、后知缺口 | 不沿用旧值，不声称设备生效 | 底层 5 项 READY/PASS，E1；记录器在线端到端故障注入 NOT_RUN |
| SC12 多实例/关闭 | 同时两份离线包；关闭其中一份；测试已有 219 域占用 | 前缀分离，只回收所属进程，明确域归属 | NOT_RUN；源码固定域选择见 F7 |
| SC13 容量与布局 | 1366×768 屏、缩放、长参数、接近事件上限、大包 | 按钮可访问、详情可滚动；无未标注截断；记录首屏/定位耗时 | NOT_RUN；950×750 的 offscreen 截图不等于真实桌面布局验收 |

建议顺序：SC09/SC11 → SC01/SC02 → SC03～SC08 → SC10 → SC12/SC13。F1～F3 修复前，不将完整离线故障定位能力签为通过。

对业务样本分别录制：探索无目标结束并存图、探索取消并存图、加载地图并重定位、多点导航取消、禁区提交成功/消费者超时。每份样本列出预期事件、实际 sequence、map/session/version、关键参数质量和缺失数据；画面仅是其中一个检查项。
