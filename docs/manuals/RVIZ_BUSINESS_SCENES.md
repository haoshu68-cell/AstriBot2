# RViz 业务场景与设备标记

## 功能边界

新增 `Astribot Workstation → 业务场景` 页面，支持 echo、冻干、酶标仪、封膜机、恒温箱开门五类业务。每类可创建多个场景实例。实例可共享同一地图，也可各自绑定独立地图。同一地图上的设备记录可以被多个场景引用。

本页管理场景、地图关联、设备标记与导航草稿，不执行开门、上下料、抓放等业务动作。设备轮廓是显示标记，不自动成为 Nav2 障碍物、禁行区或 MoveIt 碰撞对象。人工复核地图标记也不等于完成机械臂标定。

## 首次创建

1. 在现有“地图与工位”页导入已保存、已完成收尾的 Voxel-SLAM 地图会话。沿用现有地图版本、文件完整性检查和人工转运流程。
2. 申请控制权，暂停探索或结束探索并存图，等待导航、路线、机械臂规划和搬运任务结束，确认机器人停稳。
3. 打开“业务场景”，选择业务类型，点击“新建场景草稿”，填写场景 ID、名称，选择地图。ID 使用字母、数字、下划线或短横线。
4. 可以先保存一个没有设备的场景。重新选择该场景，再点击“加载选中场景与地图”。
5. 若目标地图不同，沿用 map_manager 的地图加载事务；等待地图、TF、定位、全局和局部代价地图全部就绪，场景才生效。跨楼层勾选人工转运，在“地图与工位”页完成确认。失败或重启中断后也在该页处理恢复，不能跳过恢复直接运动。
6. 若当前地图版本相同且定位已经就绪，仅切换场景绑定，不重启地图加载。选择下拉框只编辑/查看，不会自动加载。

## 标记与保存设备

1. 选中场景绑定的地图，并确认它就是当前加载地图。
2. 点击“新增设备”，填写设备 ID、名称、类型及矩形轮廓长宽。
3. 点击“地图标记设备位置和朝向”，在 RViz 地图点击并拖动设置朝向。此次点击被设备页独占消费，不会增加导航路线点。
4. 分别标记停靠位和等待位。设备位置可位于地图障碍物上；停靠位和等待位必须位于地图内的已知空闲区域。空闲栅格检查只检查点，不代表整机轮廓通行验收，后续导航仍执行现有规划与安全检查。
5. 检查位置、朝向、轮廓与停靠位，勾选“已人工复核”，点击“保存设备新版本”。没有复核也可保存草稿，但不能通过设备按钮加入导航。
6. 在设备列表重新选择或点击“重新读取选中设备”，读取刚保存的最新版本。勾选所需设备，保存场景，再重新选择并加载场景。
7. 已启用、已复核且属于活动场景的设备，可点击“将已复核停靠位加入导航草稿”。到“导航与路线”页核对并发起导航。不会自动开门或抓取。

设备中心、停靠位、等待位均使用 `map` 坐标，独立保存。设备中心显示矩形轮廓与名称，停靠/等待位显示方向箭头，当前设备草稿另用青色轮廓显示。可通过设备列表或“地图点击选择已有设备”（1 米选择半径）选择设备，使用“定位显示”移动 RViz 视角。

切换页面或取消标记会退出设备拾取模式。改变设备位置、长宽或停靠位会取消草稿的人工复核勾选。停用设备使用“设备启用”复选框并保存新版本，历史版本不物理删除。

## 版本与冲突

- 设备和场景均追加版本，保存请求携带目录版本及各自预期版本。并发编辑或旧草稿拒绝覆盖，重新读取后再编辑。
- 场景引用设备 ID + 精确版本。设备修改、停用后，原活动场景失效，新导航/路线/探索恢复/规划/搬运请求被拒绝。重新选择场景时，过期设备不会自动勾选；核对后重新勾选、保存场景、重新加载。
- 切换地图、场景或活动场景失效，会清空旧路线草稿。新保存的路线文件绑定地图及场景版本，跨上下文加载被拒绝。旧路线文件未记录这些字段，只能在未加载受管地图和场景的上下文使用；受管场景下应重新标记并保存。
- 丢失控制权、状态过期、地图事务进行中、导航/探索/规划/搬运忙时，编辑提交和加载禁用。后端同时检查这些条件，不能仅依赖界面按钮。
- 当前限制：最多 64 台设备、64 个场景，每个场景最多引用 32 台设备，每条记录最多 100 个历史版本；目录整体保留既有容量约束。容量耗尽时明确拒绝保存。

## 保存位置与旧数据

设备和场景复用 map_manager 的 `catalog.json`，与地图资产保持同一份目录，采用文件锁、原子替换和落盘同步。无需额外采集脚本。

新默认位置：

- 设置了绝对路径 `XDG_DATA_HOME`：`$XDG_DATA_HOME/astribot/map_catalog/catalog.json`。
- 否则：`~/.local/share/astribot/map_catalog/catalog.json`。
- 当前用户通常为 `/home/yjh/.local/share/astribot/map_catalog/catalog.json`，实际绝对路径显示在场景页“存储”字段。
- `map_manager.storage_root`、`map_session_adapter.asset_root` 显式配置优先。两者分别设为目录根和对应的 `assets` 子目录。

旧 `/tmp/astribot_map_catalog` 不会自动删除、复制或导入；已运行的旧程序也不会被自动切换。若需继续使用旧目录，将这两个参数分别设为 `/tmp/astribot_map_catalog` 与 `/tmp/astribot_map_catalog/assets`。如果要把旧资产迁到持久目录，建议在新目录下通过地图导入重新导入原完整会话，再创建场景。**不要仅移动 catalog.json**：现有地图记录含资产绝对路径，直接移动文件不能保证可用。

RViz 重启后从后端恢复标记；map_manager 重启后从磁盘恢复记录。恢复记录不等于地图已完成重定位，仍须加载地图并满足就绪检查。

## 接口与诊断

运行时新增功能均为 C++：

- `device_put`：设备定义与新版本。
- `scene_put`：业务类型、地图版本和设备版本引用。
- `scene_load`：显式激活场景，必要时进入地图切换事务。
- `/map_manager/status`：最新设备/场景、活动场景、场景有效性、存储路径。
- `/map_manager/events`：记录命令、版本和结果；现有诊断录制配置已经记录状态与事件，可用于复盘设备/场景上下文。
- `/operator/equipment_markers`：RViz 设备显示。使用新 `operator.rviz` 配置；已有个人 RViz 配置需添加此 MarkerArray 话题。

通过 `operator_backend` 的控制权入口提交，场景切换沿用地图管理事务。内部地图服务不是用于隔离恶意 DDS 客户端的安全边界，生产环境仍需现有 DDS 网络访问约束。
