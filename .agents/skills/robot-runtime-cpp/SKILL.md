# 实现语言与迁移约定

本技能是项目语言选择的统一入口，以用户当前要求为准：**功能实现优先 C++；只有脚本和启动文件类优先 Python。**

| 实现内容 | 默认选择 |
|---|---|
| 算法、控制、安全检查、感知、规划、任务状态机和调度 | C++ |
| ROS 节点/组件、Action/Service、SDK/协议适配、REST/MQTT 功能服务 | C++ |
| RViz/区域编辑等功能 UI、几何、数据库/账本持久化、故障与报警模块 | C++ |
| 启动文件、部署/运维辅助脚本、一次性转换、采集、回放、分析和验证脚本 | Python |

按职责分类，不按文件后缀或“薄适配”名称分类：常驻网关、执行器、业务算法和 UI 功能不能因为能写成脚本就默认选 Python。测试核心行为可使用 C++ 单元测试，Python 适合外部验证脚本；声明式配置保持项目已有格式，现有必要的 shell 包装无需为语言统一重写。

现有 Python 实现或第三方绑定可以在兼容迁移阶段保留；记录依赖和迁移边界，不把它扩张成新增 Python 业务模块的默认许可。语言偏好不授权一次性重写所有已有代码。

迁移按已定位的性能、可靠性问题和模块边界分步进行，复用已有 C++ 实现。保持接口、几何/版本、采集时刻、取消、故障、数值边界和资源预算；用相同输入、边界/故障场景及必要的隔离集成验证行为和尾延迟，不能放宽时效、碰撞或到位门槛换取通过。

报告区分建议、实现、离线、仿真和真机证据。实际涉及栈操作才加载 [ros2-stack-ops](../ros2-stack-ops/SKILL.md)，仅选择语言不要求启动环境。
