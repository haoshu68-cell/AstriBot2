# 任务状态转换与事件偏序

用于设计或修改任务取消、终态、资源交接、幂等和重启协议。以下是设计约束与可映射的
状态名称，不能据此宣称当前导航仲裁器已实现整机任务总线。

## 三类状态分别存储

| 状态轴 | 示例 | 表示什么 |
|---|---|---|
| 执行阶段 | QUEUED、PREPARING、EXECUTING、STOPPING、VERIFYING、FINALIZING | 调度器和执行者正在做什么 |
| 业务结果 | 未决、SUCCEEDED、FAILED、CANCELED、PREEMPTED、REJECTED | 对这次请求的一次持久化裁决 |
| 资源处置 | HELD、RELEASE_PENDING、RELEASED、QUARANTINED | 哪些读写权限仍不可授予其他任务 |

`RECOVERY_REQUIRED` 表示执行或资源存在未决状态。可以已有持久化的 FAILED 结果并保留
QUARANTINED 资源；不要为等资源归还无限隐藏业务失败，也不要用业务失败把资源标为空闲。
结果携带资源处置及其版本，后续交接事件更新处置视图，不能改写原结果来伪造执行成功。

中间阶段或暂停需要提前交接资源时，持久化该阶段/暂停检查点及资源处置，随后应用相同
交接条件；无需等待整项任务终态，也不能为了交接伪造任务已完成。

## 转换表

事件由任务的单一逻辑权威串行裁决，可采用队列或比较交换；不要求所有来源的消息按全局
时间排序。表中“持久化结果”包括任务/执行 ID、原因、证据和资源处置；落盘失败走恢复分支。

| 当前状态 | 事件与前置条件 | 下一阶段 / 结果 | 副作用与资源条件 |
|---|---|---|---|
| RECEIVED / NORMALIZING | 格式、授权或规范化失败 | FINALIZING / REJECTED | 无子动作；持久化拒绝与理由 |
| VALIDATING | 准入不通过且不允许排队 | FINALIZING / REJECTED | 不建立运动权限 |
| VALIDATING | 请求有效，可等待 | QUEUED / 未决 | 排队不持有运动权限 |
| QUEUED | 到期或用户取消；确认未提交子动作 | FINALIZING / CANCELED 或明确超时结果 | 无需发送虚构 cancel 或等待物理停稳；若有预留则归还对应预留 |
| QUEUED | 调度选中，能力/上下文仍有效 | ADMITTED -> RESERVED | 原子或有回滚的全资源申请；不能持有一半资源就运动 |
| RESERVED / PREPARING | 准入与起点复核通过 | EXECUTING | 记录执行 ID、step ID、lease epoch 后提交子动作 |
| RESERVED / PREPARING | 取消且能证明没有下游副作用 | FINALIZING / CANCELED | 持久化处置后归还预留；若提交结果未知，按已可能执行处理 |
| EXECUTING | 子步骤成功，步骤证据及账本一致 | 下一步骤或 VERIFYING | 下一步骤重新检查上下文和权限；正常成功不经过暂停或取消 |
| EXECUTING / PREPARING | 受理取消/抢占，可能已有副作用 | CANCEL_REQUESTED -> STOPPING | 冻结新步骤；向现有 child 发 cancel，超时按最终保护协议受控停止 |
| 执行中且可暂停 | 受理暂停 | PAUSE_REQUESTED -> PAUSED | 取得暂停安全证据后进入 PAUSED；明确哪些资源保留及哪些可交接 |
| PAUSED | 恢复请求且资源、健康、上下文复核通过 | RESUMING -> PREPARING | 不重放旧命令；从有证据的检查点重新准备 |
| VERIFYING / STOPPING | child 终态或旧执行者有效隔离，必要实测/账本检查完成 | FINALIZING / 候选结果 | 无运动步骤可按契约将物理停稳检查标为不适用；运动/保载步骤不能省略 |
| FINALIZING | 结果及资源处置持久化成功 | 业务终态；资源仍可 RELEASE_PENDING | 按下节提交资源交接；对外结果明确资源状态 |
| 任意有副作用阶段 | 状态未知、不可确认停止、失联或持久化失败 | RECOVERY_REQUIRED | 禁止新步骤，隔离受影响资源及依赖；最终保护的停止/保载不依赖日志可写 |
| 已有业务终态 | 同一请求重放或迟到事件 | 保留原结果 | 返回既有结果或更新证据/资源处置视图；不能再执行或覆盖裁决 |

本表保留业务结果的 reason code：超时、用户取消、被抢占、输入失效、定位失效和设备
故障不能全部折叠为一个“失败”文案。失败也必须标明是否仍可能运动或持有载荷。

## 提交偏序与资源交接

分别记录以下事实，不用一个 `done=true` 代替：

- C：取消被权威状态机受理（取消分支才需要）；A：下游取消回执；
- T：子执行终态；F：旧执行者被可验证地隔离，无法再向有关资源发有效命令；
- S：任务所需的实测安全状态及物体/载荷账本已核对，带来源、时效和上下文；
- R：任务结束时的业务结果，或中间交接时的阶段/暂停检查点，与资源处置已可恢复地持久化；
- H：资源持有者/epoch 转换已提交，旧权限不能再使用；N：新冲突任务获得运动权限。

必要偏序是 `C -> 冻结新步骤/发 cancel`，以及交接路径的
`(T 或具备实现证据的 F) + S + R -> H -> N`。A、T、S 的消息可能以任意顺序到达；
A 不是 T 或 S，单独 S 也不能证明旧执行者不会再次发命令。无子执行或无运动时需依据
接口契约明确对应检查“不适用”，不能为了凑步骤创建虚假反馈。

R 可记录 `release_pending`，因此不依赖 H；中间交接的 R 不提交整项任务终态。通过受持久化保护的资源状态机提交 H，使用
持有者及 lease epoch 的比较交换，防止重复释放或释放新任务租约；对外发布可用并授予 N
前必须能够恢复这一转换。若 H 失败，结果保留、资源仍不可重新授予。若 R 失败，继续
安全处置并隔离相关资源，不宣称请求已持久化完成。此顺序避免结果与资源互等。

F 是具体隔离能力的证明，例如下游确实拒绝旧 epoch；仅增加一个 epoch 字段、让本地租约
超时或进程心跳消失都不构成 F。当前后端不支持可靠隔离时必须等待确证终止并核对状态，
不能以设计字段冒充已有保护能力。实测未知、载荷未知或共享包络不一致时保持相应隔离。

只约束冲突资源及其真实依赖。夹持载荷可能使底盘、包络、场景也相关；但日志查询、只读
状态请求或已经证明无读写/运动依赖冲突的任务可以按各自准入运行，不要求全系统停摆。

## 取消竞争、幂等及旧事件

- 协议必须固定取消与完成的裁决点。可采用默认策略：业务结果提交先完成则取消返回
  `TOO_LATE` 并返回原结果；取消已被权威状态机受理则进入取消分支，之后 child 的成功
  仅作为下游事实，不直接写整机 `SUCCEEDED`。成功候选已在验证中也需参与同一原子裁决。
  若产品需要“已经完成的不可逆操作以完成为准”，必须明确另一裁决条件和证据，不能由
  两个 callback 各写终态。操作确实完成但任务已取消时，仍如实提交物体/载荷事实。
- 对每条事件核对 `task_id / execution_id / step_id / lease_epoch / event_id`。source stamp、
  receive stamp 与 clock epoch 用于追溯；决定状态的是合法转换与权限，不能只比较时间戳。
  重复事件无重复副作用；旧 execution/lease epoch 的 ACK 或结果仅保留审计，不更新当前状态。
- 幂等作用域内同键同规范化 payload 返回现有任务或结果；同键不同 payload 拒绝为
  `IDEMPOTENCY_CONFLICT`，不覆盖原请求。键到任务的映射要在可能产生外部副作用前持久化；
  无法落盘则不启动该请求，防止重启后重复执行。保留期结束后的请求策略须明确。
- 重启时区分已提交结果、进行中任务和未提交交接。已完成请求保持幂等；未决资源进入
  恢复核对，旧执行尝试不自动重放。取得新执行 epoch 不代表旧后端已停，仍需 T/F 与 S。

## 协议验证场景

| 场景 | 输入或事件序列 | 可观察的正确行为 |
|---|---|---|
| 正常成功 | 正常准入、child 成功、有效实测确认 | 直接验证并提交成功，无虚构暂停/取消；结果与资源交接分别可查 |
| 准入拒绝 | 能力/权限/上下文不满足 | 无 child 请求和运动权限；拒绝原因可回放 |
| 排队取消 | 尚无资源或下游副作用时取消 | 不向不存在的 child 发 cancel；无意义停稳屏障不阻塞结果 |
| 取消与成功竞争 | 交换两个事件的接收与处理顺序 | 同一裁决规则得到唯一业务结果；已发生物理事实仍入账 |
| 终态早于 ACK | T、S、迟到 A；或 A、T、S | 无强制 ACK 到达顺序；不因迟到 A 改写已提交结果或资源状态 |
| 停止未知 | child 报终态但速度过期、反馈缺失或载荷未知 | 隔离相应资源；不以终态或 ACK 伪造 S；允许无冲突只读请求 |
| 旧命令仍可能有效 | 本地租约超时但下游尚未停止/不拒绝旧 epoch | 不把超时当 F，不授予冲突运动权限 |
| 落盘失败 | 分别在幂等绑定、R、H 前后注入失败/崩溃 | 启动前失败无副作用；R/H 未确证时不重新授予；重启无重复执行 |
| 重启与旧 epoch | 未决任务重启，随后收到旧结果/ACK | 核对真实状态；旧事件不提交当前任务或释放新租约 |
| 幂等冲突 | 同键同 payload、同键不同 payload、终态后重放 | 分别返回已有任务、明确冲突、原结果；均不重复驱动 |
| 独立任务 | 某运动资源隔离时提交只读任务或无冲突任务 | 按真实资源/依赖检查；不会把整机所有任务无条件串行化 |

这些是协议验证设计，只有实际执行并保留输入、输出和证据后才可报告测试通过；文档推演
不能充当仿真或真机的停稳/隔离验证。
