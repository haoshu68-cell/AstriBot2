# 栈诊断经验：线索与证明分开

旧技能保存过以下故障线索。本页不重新认定历史根因，不保留旧清理脚本；当前源码/会话和连续测量优先。

## 工具 shell 与进程匹配

工具运行 shell 时，完整脚本文本可能在 shell 的命令行里。按字符串匹配进程会把查询者、并发监控或启动 shell 本身算进去，甚至终止它们。改成按文件保存匹配串也不能建立归属。要观察实际可执行令牌和已捕获的 PID 启动身份，不能用模糊命中数量下结论。

## 发现、QoS 与时钟

ROS 图中看不到节点先核对目标会话环境，不能从另一个会话“借”环境。发现到发布者也不等于订阅收到数据；比较消息类型、QoS、端点归属以及窗口内实际帧数和时间戳。

仿真时间不推进可能使依赖 ROS 时间的逻辑或日志节流表现异常，而 wall timer 仍有活动。应查看消费者实际时间源和推进范围，不能由“有状态消息”推导物理在动，也不能由“无日志”推导进程死亡。

## Gazebo 加载阻塞与渲染

历史线索包含 `gz_ros2_control` 日志停在请求 `robot_description` 附近，以及下游 controller spawner 超时。看到相同末行时，只能提出加载阻塞假设；需检查实际参数服务归属、目标 world 时间推进、相关进程状态和完整日志。单条末行不能证明死锁或因果顺序。

旧记录里有无 GUI 的运行均出现过异常，不能用 `headless` 开关作为已知根因修复。CPU 利用率不能排除 GPU/渲染、锁、单线程或调度瓶颈；需要同一场景的受控比较。话题数量、日志行数和固定 CPU 历史值只作为线索。

## 日志停止与外部干扰

先关联本会话操作时间线、退出状态、信号、超时和采样记录，再解释日志停止。信号日志可能来自正常退出、supervisor 重试、人工停止或其他来源；未确定来源时写“会话被中断，原因未确认”，不能当作稳定复现的算法故障。无数据/环境错误归基础设施或观测无效，不计为业务成功或失败。
