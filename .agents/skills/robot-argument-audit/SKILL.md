# 机器人方案论证链核查

将用户提供的批判性阅读方法改为工程论证核查；来源见 [接入记录](../../../docs/ROBOT_REVIEW_SKILLS_INTEGRATION_20260922.md)。默认只读被评材料，输出独立的主张—证据表。

## 从原文到可检验主张

1. 给输入标注文件/章节/行号、版本/hash、截断范围；先忠实说明作者想解决的问题与最强已有论据，不替作者补成已实现的设计。
2. 给影响决策的主张分配 `C-id`，关联需求 `R-id`。区分原文事实、设计目标、推断、重建的隐藏前提和改进建议。
3. 建立 `前提 A → 证据 E → 推理连接 → 主张 C → 适用范围`。证据写来源、版本、条件、采样/分母、是否独立；没有证据就明示缺失。
4. 主动寻找替代解释与最小反例：改变一个前提是否还能推出结论？结论从局部到整机、仿真到真机、接口到能力时靠什么连接？
5. 仅核查会改变决策的外部事实，用官方文档、原始论文/代码、实际记录；没有查证不写“已证实”。外部资料证明算法性质，不证明当前安装实现。

## 必须保留的语义差别

| 常见跳步 | 核查断点 |
|---|---|
| ComputeGrasps / 6D 返回成功 → 抓取完成 | 候选、IK/碰撞、执行准入、夹爪反馈、物体保持与账本缺一不可混称 |
| Gazebo attach 或 Action 成功 → 实物不滑落 | 仿真物理模型、载荷、接触/力与独立观测是否支持 |
| 地图/禁区保存、ACK → 所有消费者当前使用 | ACK 的身份、版本、时效、消费者覆盖与后续失效处理 |
| 同一 stamp / PTP 配置 → 同时曝光且新鲜 | 实际设备时间、曝光/边沿、锁定、配对、接收积压分别有证据 |
| 有 WorldSnapshot/接口/目录 → 生产闭环 | 生产者、消费者、launch 和当前安装产物实际接线 |
| 7 场景有明确响应 → 7 场景功能成功 | 正确拒绝、误拒绝、有效输出精度、无输出和功能成功分母分开 |
| 平均延迟改善 → 所有场景性能更好 | P95/最大值、并发负载、预热、同输入配对及允许退化预算 |
| 两个评审同意 → 两份独立证据 | 同一源码/数据的转述不是新增证据，相关错误仍可能共识 |

技术准确的结论也可能不支持产品需求：如安全拒绝的设计正确，但目标工况没有完成率证据，应同时保留这两个判断。

## 输出与关闭

使用 [评审记录中的论证表](../robot-design-review/assets/review-record.md)。每个 C-id 的状态选择：
`supported-in-scope / partially-supported / contradicted / insufficient-evidence / not-checked`。
`contradicted` 要有反证；证据缺失不自动判为错误，原文没有承诺的能力不当作作者缺陷。

至少输出最有支持的主张、改变决策的断点、关联证据与缺口、使该主张成立或被推翻的实验。无实质断点时如实说明。
把断点连到 `F-id → SC-id → E-id`，由 [场景边界验证](../robot-scenario-boundary-validation/SKILL.md) 设计验证；不要在核查中静默重写主张来获得“通过”。
简短审阅可只给关键论证表；跨模块或有分歧时再画 Mermaid 图（明确区分原文支持与重建假设）。
